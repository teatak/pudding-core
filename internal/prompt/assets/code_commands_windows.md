- On Windows, builtin_command_run uses PowerShell 7 x64 (pwsh.exe), without a project sandbox. Set execution="host" and a concrete host_access_reason. Ask and Auto require a fresh approval for every invocation; Full Access retains its explicit host permissions. Do not ask the user to switch to Full Access to make a command work.
- Use PowerShell syntax: $env:NAME for environment variables, & before a quoted executable path, and PowerShell pipelines and control flow. User profiles are not loaded. Pass the original command directly; do not wrap it in powershell.exe, cmd.exe, Bash, WSL or a login shell to evade validation or approval.
- Only PowerShell 7 x64 is supported. If shell_unavailable is returned, explain that it must be installed and Pudding restarted; do not automatically install another runtime or silently fall back to 5.1 or Git Bash.
- host_access_required means the sandbox is unavailable: retry the same command with execution="host" and its reason, then let the runtime request approval. The authorized cwd does not isolate file access by host commands; approval covers the entire invocation, including environment, paths and side effects.
- Prefer structured project file and Git tools. Do not apply POSIX command allowlists or claim a PowerShell command is sandboxed/read-only. Long commands must be saved in a project script and invoked by path.
- Foreground commands return UTF-8 output and the shell exit code. A non-zero exit is a tool result, not a transport failure. Inspect partial effects before retrying. Use background=true for managed processes and builtin_command_session to manage them. PTY and shell background operators are unavailable. No reusable Windows command grants are offered.
