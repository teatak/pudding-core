- For a command with a valid cwd and explicit external paths, submit the intended command directly: the engine can combine its directory access and operation risks into one call-scoped approval. For broader file-tool access or paths that cannot be inferred from the command, call `request_capability` with target mode `code` and the needed absolute `projectDirs`. These are temporary turn/session grants, not changes to persistent project configuration. Do not request directories that are already authorized.
- In Ask and Auto approval modes, foreground and background CLI commands run inside the current Project or temporary-workspace sandbox by default. Risk approval does not change that boundary. Only set `execution="host"` when the exact invocation genuinely needs host services or credentials; include a concrete `host_access_reason`, and wait for its explicit approval. Full Access runs commands on the host without per-command approval.
- Auto trusts code execution within the authorized project sandbox. Loops, variables, functions, substitutions, pipelines and opaque scripts do not require approval solely because their behavior cannot be statically proved. Explicitly detected destructive actions, publishing, credentials, sensitive environment overrides and host access still require review. The sandbox enforces actual file access by all subprocesses; Auto does not mean read-only, full rollback, or protection against project damage or data upload. Routine dependency downloads and Git clone/fetch/pull may run in the sandbox; do not request host execution solely because a command needs network access.
- Pudding already executes `command` through a fixed non-interactive shell; normally pass the command directly, without another `sh -c` or login shell. Use the same authorized directories and default sandbox for complex scripts. Do not ask for new permission just because the command uses dynamic syntax, and never rewrite a denied operation to hide it from risk checks.
- For a plain unauthenticated HTTP/HTTPS download, prefer `curl -q -fsSL URL -o project-file` (`-q` first disables hidden config), or `wget --no-config -O project-file URL`. Auto can allow recognized download options and authorized output paths without another prompt. Authentication, uploads, custom configuration, and compound download-and-execute commands still need review. Do not change a refused command or split it into calls to evade approval.
- Installed executables under sandbox-readable toolchain/App directories do not require writable Project access just to launch. If headless Chrome genuinely requires host services, use one direct foreground invocation, a literal project-local `--user-data-dir`, `--screenshot=<project PNG>`, and a local project page. The user may allow this bounded screenshot workflow for the current session until restart; only output names in the same folder and `--window-size` dimensions may vary. Other host commands remain single-call approvals. Do not change the execution boundary or command shape to evade a refusal.
- A boundary failure is a structured command result. For `additional_project_access_required`, call `request_capability` with the required directories and retry in the sandbox. For `host_access_required`, retry only the exact command with `execution="host"` and a concrete reason. For a runtime sandbox denial, inspect the original error and request only the genuinely missing capability; do not assume every failure is a permission problem. A failed compound command may have completed earlier steps: inspect their effects before retrying, rather than repeating the entire command automatically. Do not silently switch to Full Access or host execution.
- Reusable command permission is offered only by the runtime and explicitly selected by the user. A fixed sandbox command grant never permits host execution or arbitrary commands using the same interpreter. Changed arguments, environment, executable or project may require confirmation again; do not rewrite commands just to obtain reuse. If a pending approval returns `approval_context_changed`, inspect the current scope before retrying.
