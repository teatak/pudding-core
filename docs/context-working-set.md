# 模型工具结果按需读取

通过模型结果预览和精准回读减少无关内容进入上下文；不做新的会话摘要、不淘汰历史轮次、不修改推理回传协议。

## 事实源与边界

- canonical messages 保存工具的原始返回值，界面仍显示该原始结果。模型预览只是请求投影，不另建输出缓存。
- 历史构建与当前 turn 的工具循环统一调用 `tool.ModelResultContent`。预览规则不随轮次年龄变化，避免每轮改写已有请求前缀。
- 当前执行链先提交工具结果，再发送下一次模型请求，因此正在执行的 turn 也可以回读。
- 不修改工具调用/结果配对、原生 reasoning/signature、技能引用解析。用户消息、约束和回答不受本机制裁剪。

运行时控制标记只由 canonical system message 的请求投影生成。其他消息的文本和工具结果中的同名标记会在模型视图中转义，原消息与界面展示不变。若原生 provider continuation 会重放未经转义的内容，该请求改用 canonical parts 的安全投影，不改写已保存的原生状态。

## 模型视图规则

| 结果 | 规则 |
| --- | --- |
| 文件片段 | 只传 `numberedContent`，去掉重复的 `content`；原始双字段结果仍供 UI 使用 |
| 文件搜索 | 相同的 `text` / `excerpt` 去重；最多展示前 20 条命中，保留原 `matchCount` / `resultsCapped`，另标 `shown_matches` |
| 长命令结果 | stdout / stderr 分别返回可读 head / tail 与 chars / omitted_chars，保留执行边界、shell、耗时、退出事实和验证提示 |
| 长补丁结果 | 成功时保留 status、fileCount、files 及修改后的 lineRanges；shown_files 表示已展示文件数，lineRangesTruncated 标明某文件范围仅为前缀。失败时保留恢复坐标及可容纳的候选上下文；完整信息由 result_ref 回读 |
| 其他大结果 | 去重后超过 12,000 Unicode 字符，返回前 6,000 / 后 2,000 字符的预览、结果引用和关键执行状态 |
| 技能与显式历史读取 | 不套用大结果预览，避免截掉指令或对读取页再次缩略 |

只有请求暴露历史读取工具且结果有 turn / call 标识时，才使用有损预览；否则仅作无损去重。搜索少展示的命中和大结果都标记 `preview_only=true`。没有该标记不代表源工具从未截断，仍须检查其 `truncated` 等字段。

## 工具结果文本展开

开发者设置 `tool_output_text_enabled` 默认关闭。开启后，新 turn 将已声明的字符串
展开为同一条 tool result 内的正文；已有 turn（包括重启继续）保留开始时的开关快照。
工具输入 schema、执行状态和原始结果不变。未经声明的字段、没有声明的旧历史仍沿用
原格式。声明来自 `provider.ToolDef.ModelOutput` 或本次 `tool.Result.ModelOutput`，
并与结果一起持久化；不根据工具名字替旧历史补猜声明。

`ModelOutputSpec` v1 使用 `textFields` 列表。每项为 RFC 6901 `path`、可选 `title`、
可选数组路径 `each`、`optional` 和 `overflow: "excerpt" | "whole"`。有 `each` 时，
`path` 相对每个数组元素。空字符串是有效值；optional 只允许缺失，不接受 null 或
错误类型。最多 64 条规则，路径最多 4096、标题最多 256 个 Unicode 字符；标题不含
控制字符。未知版本、重复路径或错误声明保留业务结果并附展示诊断，不重做工具动作。

视图中的原字段变为 `{"$text_ref":"t1"}`，随后是同 ID、完整来源路径及可选标题的文本块。
ID 只在本条结果内有效，即使正文相同也不跨字段合并。文本按 JSON 解码一次，保留实际
LF、CRLF、tab、空行及字面量 `\n`；不会递归解析字符串内的 JSON 或反转义代码。
现有来源文字的保留标记转义仍在 provider 消息构建时执行。

首批声明覆盖命令 stdout/stderr、文件带行号正文、搜索片段和历史回读正文。文件／搜索
沿用原行号规范化，再展开文本；不会同时保留一份重复的原正文。最终文本连同元数据和
字段标签参与原 12,000 字符预算。可回读时，excerpt 使用带标记的整行 head/tail，whole
完整显示或整体省略；结果保留 result_ref。没有回读条件以及显式历史读取页不再二次截断。
`ColdResultContent` 继续使用纯 JSON 投影；冷记录清除投影视图中的声明，防止正文复活，
SQLite 原始内容及声明保持不变。

内部小组件通知从 metadata 的原 payload 投影，保持原 user 角色及原触发次数；
棋盘是普通声明字段，不在 Core 硬编码游戏规则。冷通知仍可通过 message_id 回读。
第三方 MCP 的原始 envelope 独立保存；纯文本继续保留，仅当整个文本 JSON 与
structuredContent 完全相等时，在启用开关的模型视图中去重。自有 MCP 使用
`_meta.pudding.{canonical,modelOutput}` 传递声明，不能保证其他 MCP 客户端如何组合
text 与 structuredContent。此功能不执行摘要模型，也不改变工具权限。

## 跨轮冷却

- 设置中的 `tool_result_cooling_enabled` 默认开启；`tool_result_cooling_keep_turns` 默认 2，范围 0–50，表示额外保留的已结束输入轮数。当前 turn 始终保留。此设置独立于 Compact 的保留轮数，修改轮数在下一次冷却时应用；关闭开关后构建请求恢复 L1 预览。
- 只有窗口已知、自动压缩阈值大于 0，且新 turn 第一次请求的校准输入估算达到该阈值时，才尝试批量冷却。工具循环中途不推进水位；中途超限仍按原有 Compact 处理。
- 先临时构建候选视图，只有校准后的输入确实减少且严格低于压缩阈值，才提交水位；否则直接走 Compact。不额外增加字符门槛、固定 token 门槛或超时判断。
- 较早的大型成功工具结果只保留 `cold_only`、`result_ref`、工具名、调用 ID、大小及路径、行号、退出码等元数据。模型可见内容不超过 1,200 字符、失败、技能与插件加载、表单答案、历史回读页不冷却；用户输入、回答及附件不变。
- 小组件通知共用开关、水位和收益判断。较早的大通知只保留来源、摘要、事件坐标、`cold_only`、大小与 `message_id`，通过 `builtin_history_get_message({"message_id":"…"})` 回读；通知正文与 `data` 不进入冷却视图，原始记录、界面详情和 Compact 摘要输入不变。小通知（不超过 1,200 字符）不冷却。
- 纯通知记录不占冷却或 Compact 保留的输入轮数；通知触发的 `widgetAction` 执行轮正常计数。冷却水位可覆盖冷轮之后、热轮之前的通知，但热区执行轮引用的源通知继续保留。新通知不会自行推进已提交水位。
- 水位保存在 SQLite，按历史末条及旧水位 CAS 原子提交。Builder 按已提交水位投影，后续新轮次不会自动扩大冷区。Compact 成功后在同一事务清除水位；候选 Compact 的预算也按清除后的投影检查。
- Compact 摘要输入仍读取 L1。已有冷却水位时，额外检查完整摘要输入的校准估算及余量；达到窗口 90% 则优先 Compact。候选冷却也须通过此检查，避免只看缩小后的普通请求。估算并非精确分词保证，大幅增长仍可能需要更大窗口。
- 开启冷却时，turn 结束后的后台自动 Compact 延至下一个输入的请求前决策，避免提前消耗冷却机会；手动 Compact 与工具循环中的预算检查保留。日志记录水位、保留轮数及冷却前后 token 估算；实际 cached/uncached 用量沿用请求日志。

## 回读参数

复用 `builtin_history_get_message`，不增加工具：

```json
{
  "result_ref": { "turn_id": "turn_123", "call_id": "call_456" },
  "field": "stdout",
  "unit": "lines",
  "query": "ERROR",
  "offset": 0,
  "limit": 10
}
```

- `message_id` 和 `result_ref` 二选一；原消息读取方式保持不变。
- `session_id` 默认来自工具调用所属 session，存储查询始终显式带 sessionID；不能凭另一个 session 的 turn ID 读到内容。
- `field` 可选，选择原结果 JSON 的一个顶层字段，例如 `stdout`、`stderr`、`numberedContent`、`matches`。省略时读取原结果字符串，不包含隐藏 provider state。
- `unit` 默认 `chars`：字符串解码后按 Unicode 字符分页，返回 `content`；默认 4,000，最多 8,000 字符。数组/对象在此模式下按 JSON 文本读取。
- `unit=lines` 按完整文本行读取，返回 `lines: [{line, text}]`，默认 40、最多 200 行。`text` 保留原换行符（含 CRLF），空文本没有行，末尾换行不额外产生空行。
- `unit=items` 读取完整 JSON 数组记录，返回 `items`，默认 20、最多 200 条。用于 `field=matches` 时，不会把一条搜索结果截成半段 JSON。不是数组的字段明确报错。
- 完整记录页另有 8,000 个编码后 Unicode 字符的记录数组预算；达到预算提前结束。单条记录已超限则返回 `record_too_large`，不截断、不跳过；可显式选择 `chars` 读取片段。
- `query` 仅用于 `lines`，是区分大小写、非空的单行字面量（最多 500 字符），只返回匹配行。需要上下文时，省略 `query` 并读取该位置附近的行，不必遍历整个日志。
- `offset` 始终是原字段中的零基位置，单位由 `unit` 决定；搜索不会把行重新编号。`lines[].line` 为该文本中的一基行号，并非源文件行号。`total_lines` 是原文本总行数，不是命中数。
- 用 `has_more` / `next_offset` 翻页，保持同一个 `field`、`unit` 和 `query`，不要自己用 `offset+limit` 推算。搜索页的下一位置可以跳过不匹配的行。EOF 或没有命中时不返回 `next_offset`。
- 返回 `ok` 表示读取是否成功，`result_ok` 单独保留原工具状态。重复 call ID、非法页码、缺失字段或跨 session 查询明确失败。
- 只有 `chars` 页可能在代码行或 JSON 中间分割，不应直接当完整补丁源。所有模式都是历史快照；文件若已修改，补丁前应重新读取当前源文件。

回读范围是**工具当时实际保存的返回值**；此前命令输出/搜索自身超过原有上限而未保存的部分，不会被本功能恢复。引用随会话记录保留，进程重启、会话摘要不会使原消息失效；删除会话则不再可用。

## 调用侧约束

- 复用当前上下文中已有的结果，不因进入下一轮就重复读文件或运行检查；源文件改变、需要新鲜状态或证据缺失时再刷新。
- 搜索先限制范围和数量；回读只取需要的字段、行或记录，不为恢复整份预览而机械翻页。需要穷举时仍应完整检查，不能把少量命中当作全部结果。
- 高噪声构建/测试可将完整日志保存到任务内文件，再查看真实退出码和错误片段；不能让后续 `tail` / 过滤命令掩盖原命令失败。
- POSIX 命令中可静态识别的验证调用若位于管道上游，前台结果及后台快照返回 `verificationWarning.code=pipeline_exit_status` 和操作提示。保留 shell 原退出码，不推断管道验证通过、不更换 shell 或注入 `pipefail`；普通文本中的 `|` 不触发提示。
- 本版没有增加动态工具淘汰、跨调用结果缓存或重复读取拦截器。回读页仍参与后续上下文，因此实际模型是否减少重复读取需要运行验证。

## 验证

- 无损去重、搜索数量与预览分离、失败状态不变、UTF-8 分页完整拼接。
- 完整行/数组记录分页、编码大小上限、超大单条拒绝、空结果与 EOF、关键词命中位置及精确数值/换行符保留。
- SQLite 临时库覆盖运行中回读、关闭重开、摘要后回读，以及跨 session 拒绝。
- 当前 turn 与历史构建使用相同投影；canonical 原结果和原生推理协议状态不被改写。
- 离线统计只衡量工具正文与其启发式 token 估算；实际总请求节省与额外回读次数需在真实模型任务中验证，不能把正文降幅当总上下文降幅。
