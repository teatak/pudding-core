# 吉祥物金属化改造计划

> 状态:待实施  
> 日期:2026-08-24  
> 范围:`web/src/components/Mascot.tsx`、`web/src/styles.css`  
> 方向:银灰钛金属机身、浅色磨砂面屏、少量 indigo 品牌点缀。

## 0. 结论

当前吉祥物更像紫色塑料，而不是金属。根因不是缺少渐变，而是机身、描边、凹槽和阴影都从高色度 indigo 派生，缺少金属所需的中性基色、窄亮边和明确暗边。

本次采用扁平卡通金属方案，不做写实铬合金:

1. 机身改为低色度冷银灰。
2. 保留当前嵌入式浅色面屏及其尺寸。
3. 用一条窄亮边和一条短暗边表达金属反射，不使用大面积渐变。
4. indigo 只保留为天线端点的品牌点缀。
5. 珊瑚色状态灯继续承担表情温度。
6. 红色错误态继续保留，不改变错误反馈语义。

每个阶段独立实施和验收。上一阶段未确认前，不进入下一阶段。

## 1. 当前基线与根因

当前浅色机身为 `oklch(0.61 0.19 277)`，深色机身为 `oklch(0.7 0.17 277)`。两者色度都较高，外轮廓、凹槽和阴影又继续从机身颜色派生，因此所有结构层都带明显紫色。

现有造型中应保留的部分:

- 身体、手臂、手掌和天线轮廓。
- 当前 89% 凹槽、85% 亮面屏的嵌入比例。
- 面屏与五官统一转头的运动关系。
- 48px 小尺寸表达。
- 珊瑚色状态灯。
- 红色错误吉祥物。

本次不通过以下方式制造金属感:

- 不使用整块额头高光，避免再次出现“秃顶”效果。
- 不使用多段渐变、模糊滤镜或噪点纹理。
- 不新增关节套环、铆钉或复杂机械结构。
- 不改变转头、手臂和天线动画。
- 不同时保留 indigo 机身和银灰机身两套路径。

## 2. 目标色板

### 2.1 常规状态

| 部位 | 浅色模式 | 深色模式 | 说明 |
|---|---|---|---|
| 机身 | `oklch(0.72 0.025 255)` | `oklch(0.60 0.025 255)` | 冷银灰 / 钛灰 |
| 外轮廓 | 从机身混入 34% 黑色 | 从机身混入 38% 黑色 | 保持结构清晰 |
| 面屏 | `oklch(0.94 0.018 255)` | `oklch(0.89 0.018 255)` | 保留当前高亮度，降低紫色感 |
| 面屏凹槽 | 从机身混入 38% 黑色 | 从机身混入 44% 黑色 | 表达嵌入深度 |
| 五官描边 | `oklch(0.38 0.02 255)` | `oklch(0.32 0.02 255)` | 中性石墨色 |
| 金属亮边 | `oklch(0.92 0.012 255 / 58%)` | `oklch(0.84 0.012 255 / 48%)` | 只用于左上短边 |
| 金属暗边 | `oklch(0.34 0.02 255 / 26%)` | `oklch(0.24 0.018 255 / 34%)` | 只用于右下短边 |
| 品牌点缀 | `oklch(0.62 0.18 277)` | `oklch(0.70 0.15 277)` | 仅天线端点 |
| 状态灯 | 保留现有珊瑚色 | 保留现有珊瑚色 | 不与金属色混合 |

### 2.2 错误状态

错误态继续使用红色机身，但亮边、暗边和凹槽从错误机身颜色派生，使其仍有相同的金属层级。不得把错误态改成只有状态灯变红。

## 3. 实施阶段

### 阶段 1:仅替换基础色板

修改 `web/src/styles.css` 中现有吉祥物变量:

- `--mascot-body`
- `--mascot-outline`
- `--mascot-screen`
- `--mascot-screen-groove`
- `--mascot-screen-edge`
- `--mascot-feature-outline`
- `--mascot-shadow`

本阶段不修改 SVG、不新增亮边、不改错误态。

验收:

- 银灰机身不能呈现明显蓝紫色。
- 浅色面屏仍然清晰，不像白色贴纸。
- 48px 下身体与背景有足够边界。
- 深色模式不能灰成背景的一部分。

### 阶段 2:增加扁平金属反射层

在 `Mascot.tsx` 中复用机身轮廓，新增且只新增两个装饰层:

1. 左上轮廓内侧的窄亮边。
2. 右下轮廓内侧的短暗边。

新增颜色只允许来自:

- `--mascot-metal-highlight`
- `--mascot-metal-shade`

亮边和暗边必须被限制在机身内部，不覆盖天线、面屏或五官。

验收:

- 正面能读出银灰金属，而不是普通灰色塑料。
- 高光不能横跨额头顶部。
- 48px 下不得出现杂线或锯齿。
- 转头时亮边与机身一起运动，不发生漂移。

### 阶段 3:统一手臂、手掌和天线

- 手臂、手掌和天线继续使用统一机身金属色。
- 不增加关节套环。
- 天线端点改用 `--mascot-accent`，作为唯一 indigo 品牌点缀。
- 如果 48px 下点缀过强，只降低点缀色度，不增加第二套颜色。

验收:

- 手臂与机身仍然是一个整体。
- 天线端点可识别但不抢过面屏。
- 手臂动画和天线动画保持原样。

### 阶段 4:深色模式与错误态

- 为深色模式单独定义钛灰机身、面屏、凹槽、亮边和暗边。
- 错误态继续覆盖机身、轮廓、面屏凹槽和金属反射变量。
- 不新增运行时状态或组件分支，状态差异只由现有 `data-mood` 和 CSS 变量表达。

验收:

- 深色背景下机身轮廓清楚但不过亮。
- 错误态仍能立即读成红色错误吉祥物。
- 错误态亮边不能变成粉色发光效果。

### 阶段 5:最终验收与清理

检查矩阵:

| 维度 | 场景 |
|---|---|
| 主题 | 浅色、深色 |
| 状态 | idle、thinking、ready、error |
| 尺寸 | 48px、120px |
| 姿态 | 正面、左转、右转 |
| 动画 | 眨眼、手臂、天线、错误摇头 |

完成条件:

- `npm --prefix web run build` 通过。
- `git diff --check` 通过。
- 删除临时预览页面和未使用的颜色变量。
- 不保留旧 indigo 机身路径、废弃 SVG 层或兼容分支。
- 桌面验收页面必须来自当前 Vite dev server，不使用已安装发布版。

## 4. 实施顺序与停止条件

执行顺序固定为:

```text
基础色板
  -> 用户确认
  -> 机身亮边与暗边
  -> 用户确认
  -> 天线品牌点缀
  -> 用户确认
  -> 深色/错误态
  -> 最终验收
```

出现以下情况立即停止当前阶段并回退本阶段，不修改后续阶段:

- 银灰色像普通灰色塑料。
- 高光重新形成大面积额头亮斑。
- 48px 下新增装饰变成杂线。
- 转头时装饰层与机身不同步。
- 错误态不再明显呈红色。

## 5. 第一实施项

先实施阶段 1，仅替换基础色板。该阶段不修改 `Mascot.tsx`，可以单独判断银灰钛金属方向是否成立。
