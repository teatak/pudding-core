# 吉祥物金属化改造计划

> 状态:已实施
> 日期:2026-08-24  
> 范围:`web/src/components/Mascot.tsx`、`web/src/styles.css`  
> 方向:银灰钛金属机身、浅色磨砂面屏、统一中性色调。

## 0. 结论

当前吉祥物更像紫色塑料，而不是金属。根因不是缺少渐变，而是机身、描边、凹槽和阴影都从高色度 indigo 派生，缺少金属所需的中性基色、窄亮边和明确暗边。

本次采用扁平卡通金属方案，不做写实铬合金:

1. 机身改为低色度冷银灰。
2. 保留当前嵌入式浅色面屏及其尺寸。
3. 用一条窄亮边和一条短暗边表达金属反射，不使用大面积渐变。
4. 手臂、手掌和天线均使用统一的银灰金属色。
5. 珊瑚色状态灯继续承担表情温度。
6. 错误态保留明确的红色面罩反馈，银色金属机身不变。

每个阶段独立实施和验收。上一阶段未确认前，不进入下一阶段。

## 1. 当前基线与根因

当前浅色机身为 `oklch(0.61 0.19 277)`，深色机身为 `oklch(0.7 0.17 277)`。两者色度都较高，外轮廓、凹槽和阴影又继续从机身颜色派生，因此所有结构层都带明显紫色。

现有造型中应保留的部分:

- 身体、手臂、手掌和天线轮廓。
- 当前 89% 凹槽、85% 亮面屏的嵌入比例。
- 面屏与五官统一转头的运动关系。
- 48px 小尺寸表达。
- 珊瑚色状态灯。
- 面罩集中表达的错误状态。

本次不通过以下方式制造金属感:

- 不使用整块额头高光，避免再次出现“秃顶”效果。
- 不使用多段渐变、模糊滤镜或噪点纹理。
- 不新增关节套环、铆钉或复杂机械结构。
- 不改变转头、手臂和天线动画。
- 不同时保留 indigo 机身和银灰机身两套路径。

## 2. 目标色板

### 2.1 常规状态

| 部位 | 浅色模式 | 深色模式 | 说明 |
|---|---|---|---|
| 机身 | `oklch(0.79 0.016 250)` | `oklch(0.67 0.014 250)` | 提亮的近中性冷银 |
| 外轮廓 | 从机身混入 34% 黑色 | 从机身混入 38% 黑色 | 保持结构清晰 |
| 面屏 | `oklch(0.91 0.018 95)` | `oklch(0.80 0.016 95)` | 浅暖珍珠银面屏，避免纯白或中性灰 |
| 面屏凹槽 | 从机身混入 38% 黑色 | 从机身混入 44% 黑色 | 表达嵌入深度 |
| 五官描边 | `oklch(0.38 0.02 255)` | `oklch(0.32 0.02 255)` | 中性石墨色 |
| 金属亮边 | `oklch(0.99 0.006 250 / 78%)` | `oklch(0.95 0.008 250 / 62%)` | 只用于左上固定倒角 |
| 金属暗边 | `oklch(0.30 0.012 250 / 42%)` | `oklch(0.20 0.01 250 / 46%)` | 只用于右下固定倒角 |
| 状态灯 | 保留现有珊瑚色 | 保留现有珊瑚色 | 不与金属色混合 |

### 2.2 错误状态

错误态继续使用银色金属机身，将红色限制在面罩、凹槽和五官。面罩使用低饱和粉红玻璃，眼睛改为柔和下弧闭眼，嘴巴使用单线小皱嘴，表达“沮丧/出错”而不是“愤怒”。

## 3. 实施阶段

### 阶段 1:仅替换基础色板

修改 `web/src/styles.css` 中现有吉祥物变量:

- `--mascot-body`
- `--mascot-outline`
- `--mascot-screen`
- `--mascot-screen-groove`
- `--mascot-screen-edge`
- `--mascot-feature-outline`
- `--mascot-shadow`

本阶段不修改 SVG、不新增亮边、不改错误态。

验收:

- 银灰机身不能呈现明显蓝紫色。
- 浅色面屏仍然清晰，不像白色贴纸。
- 48px 下身体与背景有足够边界。
- 深色模式不能灰成背景的一部分。

### 阶段 2:增加扁平金属反射层

在 `Mascot.tsx` 中复用机身轮廓，新增且只新增两个装饰层:

1. 左上轮廓内侧的窄亮边。
2. 右下轮廓内侧的短暗边。

新增颜色只允许来自:

- `--mascot-metal-highlight`
- `--mascot-metal-shade`

亮边和暗边必须被限制在机身内部，不覆盖天线、面屏或五官。

验收:

- 正面能读出银灰金属，而不是普通灰色塑料。
- 高光不能横跨额头顶部。
- 48px 下不得出现杂线或锯齿。
- 转头时亮边与机身一起运动，不发生漂移。

### 阶段 3:统一手臂、手掌和天线

- 手臂、手掌和天线继续使用统一机身金属色。
- 不增加关节套环。
- 天线端点继续使用机身金属色，不增加其他颜色。

验收:

- 手臂与机身仍然是一个整体。
- 天线端点与天线杆连接自然，不抢过面屏。
- 手臂动画和天线动画保持原样。

### 阶段 4:深色模式与错误态

- 为深色模式单独定义钛灰机身、面屏、凹槽、亮边和暗边。
- 错误态只覆盖面屏、面屏凹槽、面屏边缘和五官颜色，不覆盖机身、轮廓与金属反射变量。
- 不新增运行时状态或组件分支，状态差异只由现有 `data-mood` 和 CSS 变量表达。

验收:

- 深色背景下机身轮廓清楚但不过亮。
- 错误态仍能通过粉红面罩和沮丧表情立即识别。
- 错误态不能重新扩大为整机红色，也不能呈现愤怒或攻击感。

### 阶段 5:最终验收与清理

检查矩阵:

| 维度 | 场景 |
|---|---|
| 主题 | 浅色、深色 |
| 状态 | idle、thinking、ready、error |
| 尺寸 | 48px、120px |
| 姿态 | 正面、左转、右转 |
| 动画 | 眨眼、手臂、天线、错误摇头 |

完成条件:

- `npm --prefix web run build` 通过。
- `git diff --check` 通过。
- 删除临时预览页面和未使用的颜色变量。
- 不保留旧 indigo 机身路径、废弃 SVG 层或兼容分支。
- 桌面验收页面必须来自当前 Vite dev server，不使用已安装发布版。

## 4. 实施顺序与停止条件

执行顺序固定为:

```text
基础色板
  -> 用户确认
  -> 机身亮边与暗边
  -> 用户确认
  -> 手臂与天线统一验收
  -> 用户确认
  -> 深色/错误态
  -> 最终验收
```

出现以下情况立即停止当前阶段并回退本阶段，不修改后续阶段:

- 银灰色像普通灰色塑料。
- 高光重新形成大面积额头亮斑。
- 48px 下新增装饰变成杂线。
- 转头时装饰层与机身不同步。
- 错误态面罩不再明显呈红色。

## 5. 第一实施项

先实施阶段 1，仅替换基础色板。该阶段不修改 `Mascot.tsx`，可以单独判断银灰钛金属方向是否成立。

## 6. 后续表情优化

- 普通状态取消白色眼框，只保留深色椭圆瞳孔。
- 瞳孔调整为 `5.6×7`，双眼中心距设为 `24`，继续复用现有瞳孔跟随。
- 保留单个眼神高光，不增加动漫式多层高光。
- 错误态使用柔和下弧闭眼和单线小皱嘴，不显示腮红。
