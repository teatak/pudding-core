# 工作区优化改造方案与实施计划

> 日期：2026-09-05
> 状态：待实施。本次交付设计和实施文档，尚未修改产品行为。
> 范围：Electron 桌面端的工作区组织、应用切换、标签、资料库与专注模式。
> 依据：本轮产品讨论及当前源码核对。后续实施以本文件的验收项逐阶段交付。

## 1. 已确认的方向

工作区采用“统一外壳、专用应用、共享资料”的组织方式。

1. 顶层固定为 **项目、浏览器、产物、资料库** 四个入口。
2. 项目借鉴 VS Code 的操作方式，保留目录、文件编辑、内容搜索和 Git。
3. 浏览器借鉴 Chrome 的操作方式，拥有自己的网页标签、地址栏和导航工具。
4. 产物工作台管理 Pudding 原生表格、画布、图表等产物。“Office”只是编辑体验的类比，不代表 Word/Excel 文件，不引入 `.docx`、`.xlsx` 作为原生产物模型。
5. 资料库统一查找、收藏和重新打开资料，各类型继续使用原有内容及存储模型。
6. 各应用管理自己的标签和操作状态，顶层入口数量不随打开内容数量增长。
7. 专注模式扩大工作区，同时保留可用的对话。对话位置支持左侧、右侧、底部，统一到一个“专注”入口。

第一版采用固定应用切换和专注布局。自由漂浮窗口、桌面 Dock、应用内左右分屏、手动命名标签组和新编辑器引擎不属于本次改造。现有原生画布自身的布局能力继续保留。

## 3. 工作区外壳与四个应用

### 3.1 外壳负责什么

- 顶部应用切换，以及常驻的“新建”和“专注”入口。
- 当前工作区所属会话、项目或临时目录的明确上下文。
- 将资料打开请求路由到对应应用。
- 协调布局与可见性，不接管文件内容、浏览器实例或产物内容。

应用导航占用现有窗口顶部的工作区区域，与对话标题对齐。应用内部的标签及工具放在其内容区域上方，不再保留一行只有“工作区”标题的空白栏。

不增加横跨所有应用的竖向窄条。项目目录工具区仅在项目应用内出现，浏览器与产物不为它永久预留宽度。

### 3.2 应用职责

| 应用 | 导航与内容 | 必须保留的能力 |
| --- | --- | --- |
| 项目 | 项目根目录；文件/搜索/Git 工具区；文件与差异标签；编辑或预览区 | 多根目录、临时会话目录、文件操作、内容搜索、现有编辑与预览能力、Git 分支/变更/暂存/提交/同步、未保存提示 |
| 浏览器 | 网页标签；地址栏；后退/前进/刷新；网页内容 | 新建和关闭标签、现有历史、登录态、滚动和表单状态、查找、凭据及现有浏览器工具能力 |
| 产物 | 原生产物标签；当前类型适用的工具；内容区域 | 表格、画布、图表、Markdown、图册、组合视图、指标、时间线等现有类型；保存、恢复、导出及实际具备的编辑能力 |
| 资料库 | 最近、收藏、网页历史、产物、项目文件等视图；搜索；来源信息 | 查找、筛选、定位来源、进入对应应用；已收藏与最近关闭内容的找回 |

“产物”应用不承诺所有类型都具备相同编辑能力。按现有类型能力展示操作，不为布局统一补造无功能按钮。

无项目的会话仍可访问已有临时目录；完全没有可用根目录时，项目入口提供明确的打开目录引导。不能因为关闭了某个标签就让项目功能消失。

### 3.3 新建入口

“新建”是创建操作的唯一公共菜单，不再容纳历史、收藏或最近关闭列表。

| 动作 | 行为 |
| --- | --- |
| 浏览器标签 | 为明确的目标 session 创建新标签，进入浏览器应用并激活；浏览器内部的 `+` 调用相同行为 |
| 项目文件/文件夹 | 在明确的根目录和路径下创建，复用现有文件操作与校验；成功后进入项目应用 |
| 原生产物 | 只展示已具备真实创建链路的类型，创建成功后进入产物应用；缺少创建链路的类型不能冒充已实现 |

创建菜单、应用内按钮、会话消息中的打开动作复用同一组路由/命令，不各写一套 session 选择与创建逻辑。

## 4. 标签管理规则

### 4.1 分层与打开行为

- 顶层四个应用入口固定且不可作为内容标签关闭。
- 项目文件和项目差异进入项目内部标签；原生表格、画布等进入产物内部标签；网页进入浏览器内部标签。
- 项目相关独立文件预览和 turn diff 迁入项目查看区。附件、临时路径等不能解析成项目文件时，继续使用已有文件预览承载方式，不伪造项目根路径。
- 当前应用没有打开内容时显示自己的起始页；关闭最后一个内容标签不关闭整个应用或工作区。
- 切换应用保留该应用的选中内容、标签顺序、编辑状态、滚动状态和工具区选择。
- 从资料库打开已经存在的内容，定位到对应应用和标签；浏览器显式“新建标签”仍允许用户打开同一 URL 的多个独立标签。

### 4.2 临时预览与保留

- 项目继续使用现有单个临时预览槽和保留标签机制。
- 编辑文件后不得被下一次临时预览替换；关闭涉及未保存内容时走现有保存/放弃/取消流程。
- 不把“单个临时预览”强加给浏览器。网页有导航、登录和表单状态，显式打开的标签应独立存在。
- 原生产物按内容 ID 定位已打开标签。具体编辑器有本地草稿时，关闭前沿用它的保存规则。
- 后台工具创建资源不等于必须切换用户当前应用。复用现有 reveal 语义，区分明确的用户打开动作与后台资源更新。

### 4.3 标签过多

- 标签栏保持单行，按可用宽度展示，不设全应用统一的“两三个标签”硬上限。
- 给标题保留可读的最小宽度，剩余内容通过“已打开 N”列表查找和切换。
- 列表支持当前应用内的名称搜索；路径、域名、产物类型用于区分同名内容。
- 活动标签始终可定位，关闭非活动标签不改变当前内容，切换标签不自动重排用户顺序。
- 保留拖动排序；批量关闭复用逐项关闭保护，不能绕过未保存提示。
- 首版由应用天然完成分类，不引入自动分组、手动命名组和多套“最近标签”导航。

## 5. 统一专注模式

### 5.1 单一入口与状态

顶部使用“专注 ▾”组合入口：主按钮一键进入/退出，菜单调整对话位置并提供“收起工作区”。

| 当前状态 | 主按钮 | 执行动作 | 结果 |
| --- | --- | --- | --- |
| 工作区收起 | 打开工作区 | 打开 | 恢复普通工作区及上次应用 |
| 普通工作区 | 专注 | 进入专注 | 应用记住的专注对话位置，收起全局导航，扩大工作区 |
| 专注工作区 | 退出专注 | 退出 | 恢复普通布局、导航状态和分栏比例 |
| 普通/专注工作区 | 菜单：收起工作区 | 收起 | 回到完整对话；正在处理的资源和应用状态保留 |

在普通状态下选择专注位置，直接按该位置进入专注；已专注时即时调整位置。位置偏好记住，下次主按钮使用该偏好。

“退出专注”与“收起工作区”是不同动作，不共用关闭资源的代码路径。

### 5.2 三种对话位置

| 位置 | 对话保留方式 | 工作区布局 |
| --- | --- | --- |
| 左侧对话（默认） | 可滚动消息列表，输入框固定底部 | 对话区右侧获得剩余空间 |
| 右侧对话 | 与左侧相同 | 对话区左侧获得剩余空间 |
| 底部对话条 | 常驻输入框、当前任务/最近回复，可展开完整对话 | 为对话条及其展开高度实际预留空间 |

侧边对话初始参考宽度为 300–360px，允许拖动；最终默认值结合现有最小宽度约束在开发环境验证后写入统一布局常量。窄窗口仍保留输入能力，不静默把用户选择切换成其他位置。

底部模式要求：

- 紧凑状态复用现有当前 turn 控制台的任务状态、队列、停止、引导和输入能力。
- 增加“展开对话”，可访问完整历史和会话搜索；复用现有 transcript/query/overlay，不维护第二份消息数据。
- 展开区参与真实布局，输入框仍在底部；浏览器 viewport、表格和画布随之缩放，不能被覆盖。
- 审批、用户输入请求、失败和待发送队列可见且可处理，不能因为折叠而卡住任务。
- 浏览器现有的局部“隐藏底部输入区”入口删除；所有应用遵循同一保留对话规则。

### 5.3 进入、切换与恢复

- 专注是前端展示状态，不是后端业务 focus，不新增 `/focus` 或 daemon focus 状态。
- 进入专注不覆盖普通布局偏好。导航折叠、侧边宽度、底部高度由当前展示模式推导。
- 普通与专注的布局参数分别保留，各自只维护一份；退出时恢复普通参数，而非再估算宽度。
- 切换项目/浏览器/产物/资料库时专注状态不变。
- 切换会话时使用对应会话的工作区状态，不能让另一会话的输入目标、标签或 UI context 泄漏进来。
- 窗口变小后恢复原比例须受当前尺寸约束，不能恢复到窗口外。重新拉大时仍使用同一布局参数来源。
- 输入法组合、应用内 Escape、菜单、对话框及编辑器快捷键优先；不为专注新增会抢占输入的全局按键处理。

## 6. 资料库与内容生命周期

### 6.1 统一入口，保留真实来源

资料库是已有内容的统一查询和打开视图，不复制项目文件、网页历史或产物正文。

每条结果至少显示标题、类型、来源；同名文件显示目录，网页显示域名/URL，产物显示类型和来源会话。搜索和筛选后保留当前状态，返回资料库可继续之前的查找。

范围必须与现有数据一致：

- 项目文件：当前会话解析出的项目或临时根目录。
- 活动原生产物：当前会话内容。
- 已收藏原生产物：现有本地个人收藏库，保留来源会话和保存版本。
- 网页历史：现有本地全局历史，不能标成“仅当前项目历史”。
- 请求的 actor session 必须明确传递；全局收藏被打开时，仍按现有规则进入目标会话的工作副本。

项目文件视图与项目应用共用根目录、树查询、内容标识和打开命令。资料库中的浏览不是第二套项目编辑器。

### 6.2 搜索与历史

- 公共搜索按标题、文件名/路径、URL 和已有可检索元数据查找。
- 文件内容全文搜索仍由项目应用负责；可从公共搜索明确进入该能力，不混淆两种搜索范围。
- 已有网页历史按 URL 合并、按最近访问排序；首版沿用此语义，不伪造每次访问事件和访问次数。
- 当前历史默认返回 20 条，单次最多 100 条，最多保留 1000 条。页面必须说明实际展示范围；要支持完整翻页，在历史接口中补齐真正的分页与契约测试，不能把当前返回的部分数据称为全部历史。
- 关闭网页标签不删除历史；清空历史不关闭网页、不移除网页收藏。
- “最近”按真实打开/访问时间展示。对尚无持久化最近打开记录的类型，明确新增记录需求，不使用创建时间冒充访问时间。

### 6.3 收藏语义

第一步把现有已收藏产物完整接入资料库，保持 `SavedCanvasItem`、工作副本、revision、savedDirty 和冲突检测。

随后统一文件、网页、产物的收藏交互：

- 文件与网页收藏保存持久化资源引用，不存成 localStorage UI 偏好，也不复制文件或网页正文。
- 原生产物现有收藏内容不能降级成一个星标后丢失保存版本。收藏关系与保存内容分别明确，保存版本仍由既有产物服务负责。
- 取消收藏只移除收藏关系；删除保存内容必须是明确命名的独立动作。现有删除收藏 API 会删除保存实体，不能直接绑定到新的普通星标取消动作。
- 若为跨类型收藏增加关系表，现有 SavedCanvasItem 是内容实体，不再另存第二份产物收藏布尔值；已有收藏在一次性数据迁移中建立关系。
- 旧的全局收藏范围、内容 ID、来源和 revision 必须保留。迁移期间不自动按标题去重，不把不同版本合并成同一份。
- 文件移动、重命名后使用现有项目事件更新引用；原路径消失时明确展示不可用来源，不猜测同名文件替代。
- 网页收藏以可重新打开的 URL 引用为主，不能只依赖可能被清理的历史 ID。

跨类型收藏是本次新增的持久数据需求，须连同 Go/SQLite、API/Zod、查询缓存和迁移测试交付。仅统一前端菜单不算完成该阶段。

### 6.4 关闭、保存、删除

| 操作 | 目标行为 |
| --- | --- |
| 切换应用/进入或退出专注 | 改变展示，不关闭资源或提交编辑 |
| 收起工作区 | 隐藏工作面，保留应用状态与浏览器运行实例 |
| 关闭文件查看 | 移除文件标签，文件不删除；未保存修改按既有规则处理 |
| 关闭原生产物查看 | 移除打开引用，已持久化产物仍可在资料库找回，不调用删除内容接口 |
| 关闭浏览器标签 | 关闭该 tab 的运行实例，保留独立历史和收藏；浏览器 unload 保护沿用现有行为 |
| 保存原生产物 | 按原生内容和保存版本规则提交，冲突不静默覆盖 |
| 删除原生产物/保存内容 | 独立的明确删除动作，沿用真实删除所需确认与来源校验 |

新增内容查询与“已打开标签”必须分离。关闭产物标签后，后续 refetch 不能因为内容仍存在而自动把标签重新打开。

旧的最近关闭产物记录继续可查、可恢复。先完成恢复入口和数据核对，再迁移旧记录；本轮不因调整 UI 清空旧收藏、历史或关闭记录。

## 7. 工程边界与状态所有权

### 7.1 状态分工

| 数据/状态 | 唯一事实源 |
| --- | --- |
| 当前页面和 selected session | TanStack Router；保留显式主/副会话工作区路由 |
| 工作区展示状态、当前应用、布局偏好 | 前端本地 UI 状态；按 session 区分工作区，位置/宽度作为 UI 偏好保存 |
| 项目内部文件标签、目录展开、选中项 | 既有项目 workspace 状态；如迁移，必须同时迁移调用者并删除旧存储路径 |
| 浏览器 tab 集合、URL、导航状态 | BrowserHost 快照及现有 REST/事件链路 |
| 浏览器用户选中标签及排序 | 应用本地 UI 状态；不得再与混合标签栏双向同步 |
| WebView mount 与 presentation | BrowserRuntimeProvider；不随应用组件是否可见而销毁 |
| 原生产物、保存版本、历史和收藏关系 | daemon/SQLite 与对应服务；TanStack Query 缓存 |
| 原生产物打开引用、应用内选中内容 | 前端按会话的 UI 状态，只存 ID/顺序等，不复制正文 |
| 对话内容与实时状态 | canonical messages query + SSE overlay，完整/紧凑对话共用 |

壳只保存它负责的状态，不镜像每个应用已经拥有的全部状态。壳展示状态采用一个互斥值表达“收起/普通/专注”，不要叠加独立的 open、maximized、focus、floating 布尔值形成非法组合。

跨应用打开命令显式接收目标 session 与资源引用。项目使用根目录和路径标识，浏览器 tab 使用 sessionID + tabID，原生产物使用其现有 ID，保存实体使用 saved ID；不能用标题作为身份。

### 7.2 必须遵守的边界

- 全部业务 API 显式传递 sessionID。资料库不能隐式读取“当前会话”来决定写入目标。
- 保持 REST/SSE/WS 和 Electron IPC 既有边界，不为布局新增后台 focus 或无 session 主路径。
- `ui_context` 继续描述用户实际查看的应用与资源；从后台工具产生的更新不能篡改可见上下文。
- UI 应用不是插件/App 包机制，不为四个固定入口新建插件加载层。
- 不改变工具名称或 schema；若实施确需变更，同步处理 transcript 显示名与三语言文案。
- shadcn 官方组件按仓库要求引入，扩展能力放业务包装组件；加载状态继续使用统一 Spinner。

### 7.3 持久化和迁移

- 迁移前列出当前工作区、对话位置、项目标签、分栏比例等 UI key，以及收藏/关闭记录相关表。
- 原混合标签按类型拆入应用，保留同一应用内原顺序，并由原活动标签确定 activeApp；项目自己的文件标签不再复制一份。
- 已失效的运行 tab ID 不自动创建新 WebView；恢复浏览器按已有运行时生命周期处理。
- 对仍在编辑的文件和产物，先确保状态所有者稳定再移动 UI，不能用卸载重建掩盖迁移问题。
- 有效 UI 偏好做一次性版本迁移，成功后只读写新模型。旧 reader/writer、混合排序和双向同步路径随迁移删除。
- 数据表迁移与 UI 偏好迁移分开。收藏正文与 revision 不进入浏览器 localStorage。
- 数据迁移的重复执行、旧数据保留和重启结果必须有临时数据库测试；产品读取路径不长期保留两套新旧协议。
