## 1. 已确认的方向

工作区采用统一内容标签栏。项目作为一个完整工作区与网页、画布并列，文件仍属于项目内部。

1. 顶部只有一层标签，项目、网页和画布共用同一选中项与排序。
2. 项目默认打开，支持拖拽、关闭；关闭入口不关闭内部文件、不丢失编辑状态。资源库提供「打开项目」，文件打开请求也会重新打开项目。
3. 浏览器标签下显示地址栏及导航工具，原生 WebView 继续由现有运行时保活。
4. 画布标签直接显示对应原生内容；关闭查看不删除 canonical 内容，保存版本及冲突保护保留。
5. + 进入资源库；资源库作为空态页，提供打开项目、新建浏览器标签页、收藏、最近打开和搜索。无标签时隐藏 +，页面背景与工作区一致，去掉横线。
6. 顶部使用旧版 28px 高、默认 112px 宽的圆角标签，标题渐隐，选中项有底色；+、专注和工作区开关共用头部中心线。项目内部文件标签沿用原样式。
7. 专注保留左侧对话；专注与工作区开关只显示图标和 tooltip。
8. 关闭活动标签按混合顺序选择右邻、左邻；最后一个关闭后显示资源库。批量关闭先检查未保存画布，取消时整批保持打开。

以下阶段记录保留实施过程；早期「四应用入口 + 应用内部标签」及不可关闭项目入口的方案已由上述结构替代。

## 3. 工作区外壳与内容

- 外壳负责一层标签、显示状态与资源路由，不接管文件、网页或画布内容。
- 项目标签内保留目录、搜索、Git、文件编辑、临时预览与未保存保护。
- 网页和画布按内容 ID 直接切换。顶部 `+` 进入资源库空态页，由页面中的按钮新建网页；文件与文件夹在项目树内创建，画布继续由已存在的对话/工具/资源库链路打开。
- 移除独立资源库图标；标签栏的 `+` 是资源库入口。关闭项目后，从资源库的「打开项目」恢复已有项目界面。
- 所有资源打开、保存、关闭请求继续明确携带目标 sessionID。切换内容、专注和收起工作区不得重建 WebView。

## 4. 标签管理规则

### 4.1 统一顺序与打开行为

- 每个会话仅持久化一份顶部 `tabOrder` 与 `activeTab`，项目入口、网页、画布均属于这个顺序。
- 项目内部的文件、Git diff 及附件预览继续使用已有项目文件状态，不进入顶部标签数组。
- 项目、网页和画布可混合拖拽，限制在当前标签栏横向移动；超出宽度时横向滚动，不保留顶部数量与弹出列表。
- 切换标签保留编辑与滚动状态。关闭项目标签只关闭查看入口，内部文件状态保留；显式打开项目或项目文件时恢复。
- 项目、网页及画布全部关闭后显示资源库，不自动创建网页或重新打开项目。
- 从资源库打开既有内容时定位原标签；显式新建网页仍允许相同 URL 的独立标签。

### 4.2 临时预览与保留

- 项目继续使用现有单个临时预览槽和保留标签机制。
- 编辑文件后不得被下一次临时预览替换；关闭涉及未保存内容时走现有保存/放弃/取消流程。
- 不把“单个临时预览”强加给浏览器。网页有导航、登录和表单状态，显式打开的标签应独立存在。
- 原生产物按内容 ID 定位已打开标签。具体编辑器有本地草稿时，关闭前沿用它的保存规则。
- 后台工具创建资源不等于必须切换用户当前应用。复用现有 reveal 语义，区分明确的用户打开动作与后台资源更新。

### 4.3 标签过多

- 标签栏保持单行，按可用宽度展示，不设全应用统一的“两三个标签”硬上限。
- 顶部标签从 112px 随可用空间逐步压缩，达到 80px 最小宽度后再横向滚动。
- 项目内部的文件列表仍支持名称搜索和路径显示。
- 活动标签始终可定位，关闭非活动标签不改变当前内容，切换标签不自动重排用户顺序。
- 保留拖动排序；批量关闭复用逐项关闭保护，不能绕过未保存提示。
- 首版由应用天然完成分类，不引入自动分组、手动命名组和多套“最近标签”导航。

## 5. 统一专注模式

### 5.1 单一入口与状态

顶部直接显示“专注 / 退出专注”和“收起工作区”，不设对话位置菜单。收起工作区后只显示“打开工作区”。

| 当前状态 | 按钮 | 执行动作 | 结果 |
| --- | --- | --- | --- |
| 工作区收起 | 打开工作区 | 打开 | 恢复普通工作区及上次内容 |
| 普通工作区 | 专注 | 进入专注 | 收起全局导航，左侧保留完整对话，扩大右侧工作区 |
| 专注工作区 | 退出专注 | 退出 | 恢复普通布局、导航偏好和分栏比例 |
| 普通/专注工作区 | 收起工作区 | 收起 | 回到完整对话；保留资源和应用状态 |

“退出专注”与“收起工作区”是不同动作，不共用关闭资源的代码路径。

### 5.2 固定左侧对话

- 复用完整 Transcript 和 Composer，保留历史搜索、审批、输入请求、队列、引导与停止。
- 每次进入专注时，对话宽度重置为 340px（同时是最小宽度）；支持拖动与分隔条方向键调整，调整只在当前会话的本次专注期间保留，不写入 localStorage。
- 右侧工作区使用剩余宽度；在桌面最小窗口 560px 下，优先保留 340px 对话和至少 220px 工作内容区域。
- 不保留右侧对话、底部对话条及浏览器隐藏输入区的状态、控件和渲染分支。
- 对话顶部与输入框共用第一档紧凑断点：输入框内容宽度不超过 36rem（默认 576px，对应包含两侧留白及边框的对话栏 618px）时，审批等辅助文字隐藏，顶部同时隐藏项目名称和斜线，保留项目文件夹图标。App 在窄栏显示第一个图标及 `+N`（剩余数量），仅一个 App 时不显示数量入口；宽栏不超过 6 个时全部显示，超过 6 个时显示前 5 个及 `+N`。点击数量入口展开完整列表，保留查看和关闭 App 的能力，拉宽后同步恢复；不再按顶部剩余空间单独判断。模型名称仍沿用输入框更窄的第二档规则。
- 主副会话分屏中，专注展示当前工作区所属会话；退出后恢复原分屏。请求仍显式带 sessionID。

### 5.3 进入、切换与恢复

- 专注是前端展示状态，不是后端业务 focus，不新增 `/focus` 或 daemon focus 状态。
- 进入专注不覆盖普通布局偏好。导航折叠与对话宽度由当前展示模式推导。
- 普通分栏比例独立持久化；专注宽度仅作为每会话的临时 UI 状态，退出或收起后清除。退出时恢复普通参数，而非再估算宽度。
- 切换项目/浏览器/画布/资源库时专注状态不变。
- 切换会话时使用对应会话的工作区状态，不能让另一会话的输入目标、标签或 UI context 泄漏进来。
- 窗口变小后恢复原比例须受当前尺寸约束，不能恢复到窗口外。重新拉大时仍使用同一布局参数来源。
- 输入法组合、应用内 Escape、菜单、对话框及编辑器快捷键优先；不为专注新增会抢占输入的全局按键处理。

## 6. 资源库与内容生命周期

### 6.1 统一入口，保留真实来源

资源库是已有内容的统一查询和打开视图，不复制项目文件、网页历史或产物正文。

每条结果至少显示标题、类型、来源；同名文件显示目录，网页显示域名/URL，产物显示类型和来源会话。搜索和筛选后保留当前状态，返回资源库可继续之前的查找。

范围必须与现有数据一致：

- 项目文件：当前会话解析出的项目或临时根目录。
- 画布标签与最近关闭：当前会话的同一份持久内容，前端打开引用决定展示位置。
- 已收藏原生产物：现有本地个人收藏库，保留来源会话和保存版本。
- 网页历史：现有本地全局历史，不能标成“仅当前项目历史”。
- 请求的 actor session 必须明确传递；全局收藏被打开时，仍按现有规则进入目标会话的工作副本。

项目目录和文件搜索保留在项目应用。文件不再提供收藏，资源库通过最近打开记录定位原文件，不再建项目树。

### 6.2 搜索与历史

- 公共搜索按标题、文件名/路径、URL 和已有可检索元数据查找。
- 文件内容全文搜索仍由项目应用负责；可从公共搜索明确进入该能力，不混淆两种搜索范围。
- 已有网页历史按 URL 合并、按最近访问排序；首版沿用此语义，不伪造每次访问事件和访问次数。
- 当前历史默认返回 20 条，单次最多 100 条，最多保留 1000 条。页面必须说明实际展示范围；要支持完整翻页，在历史接口中补齐真正的分页与契约测试，不能把当前返回的部分数据称为全部历史。
- 关闭网页标签不删除历史；清空历史不关闭网页、不移除网页收藏。
- “最近打开”合并既有网页访问历史与文件、画布的真实打开时间，可筛选类型。文件/画布只在实际展示时记录，不使用创建或修改时间冒充访问时间；重复查看更新原引用。网页和文件/画布各保留最多 1000 个引用，合并后最多返回最近 100 条匹配记录。

### 6.3 收藏语义

第一步把现有已收藏产物完整接入资源库，保持 `SavedCanvasItem`、工作副本、revision、savedDirty 和冲突检测。

收藏只包含网页和画布（2026-09-05 最新确认）：

- 网页收藏保存持久化 URL 引用；文件通过项目树和最近打开访问，不单独收藏。收藏不存成 localStorage UI 偏好，也不复制网页正文。
- 原生产物现有收藏内容不能降级成一个星标后丢失保存版本。收藏关系与保存内容分别明确，保存版本仍由既有产物服务负责。
- 取消收藏只移除收藏关系；删除保存内容必须是明确命名的独立动作。现有删除收藏 API 会删除保存实体，不能直接绑定到新的普通星标取消动作。
- 若为跨类型收藏增加关系表，现有 SavedCanvasItem 是内容实体，不再另存第二份产物收藏布尔值；已有收藏在一次性数据迁移中建立关系。
- 旧的全局收藏范围、内容 ID、来源和 revision 必须保留。迁移期间不自动按标题去重，不把不同版本合并成同一份。
- 文件最近打开记录随移动、重命名更新引用；原路径消失时明确展示不可用来源，不猜测同名文件替代。
- 网页收藏以可重新打开的 URL 引用为主，不能只依赖可能被清理的历史 ID。

跨类型收藏是本次新增的持久数据需求，须连同 Go/SQLite、API/Zod、查询缓存和迁移测试交付。仅统一前端菜单不算完成该阶段。

### 6.4 关闭、保存、删除

| 操作 | 目标行为 |
| --- | --- |
| 切换应用/进入或退出专注 | 改变展示，不关闭资源或提交编辑 |
| 收起工作区 | 隐藏工作面，保留应用状态与浏览器运行实例 |
| 关闭文件查看 | 移除文件标签，文件不删除；未保存修改按既有规则处理 |
| 关闭原生产物查看 | 移除打开引用，已持久化产物仍可在资源库找回，不调用删除内容接口 |
| 关闭浏览器标签 | 关闭该 tab 的运行实例，保留独立历史和收藏；浏览器 unload 保护沿用现有行为 |
| 保存原生产物 | 按原生内容和保存版本规则提交，冲突不静默覆盖 |
| 删除原生产物/保存内容 | 独立的明确删除动作，沿用真实删除所需确认与来源校验 |

新增内容查询与“已打开标签”必须分离。关闭产物标签后，后续 refetch 不能因为内容仍存在而自动把标签重新打开。

旧的最近关闭快照通过 schema v13 → v17 合并迁移一次性迁回 `canvas_items`，保留会话、内容 ID、正文和窗口数据；已有同 ID 内容优先，不用旧快照覆盖当前版本。删除旧快照表和 REST 路径。

新关闭操作仅在每会话工作区 UI 偏好中保存内容 ID 与实际关闭时间，正文始终来自 `canvas_items`。最近关闭直接查询这些引用对应的原内容，不再复制快照，也不按 20 条淘汰内容。恢复只重新打开同一 ID；移除原“清空”入口，删除内容必须通过明确的删除动作和确认。迁入内容的 `visible=false` 只用于初始化已关闭 UI 状态，此后关闭/打开不写后端可见性。

## 7. 工程边界与状态所有权

### 7.1 状态分工

| 数据/状态 | 唯一事实源 |
| --- | --- |
| 当前页面和 selected session | TanStack Router；保留显式主/副会话工作区路由 |
| 工作区展示状态、当前应用、布局偏好 | 前端本地 UI 状态；按 session 区分工作区，位置/宽度作为 UI 偏好保存 |
| 项目内部文件标签、目录展开、选中项 | 既有项目 workspace 状态；如迁移，必须同时迁移调用者并删除旧存储路径 |
| 浏览器 tab 集合、URL、导航状态 | BrowserHost 快照及现有 REST/事件链路 |
| 浏览器用户选中标签及排序 | 应用本地 UI 状态；不得再与混合标签栏双向同步 |
| WebView mount 与 presentation | BrowserRuntimeProvider；不随应用组件是否可见而销毁 |
| 原生产物、保存版本、历史和收藏关系 | daemon/SQLite 与对应服务；TanStack Query 缓存 |
| 原生产物打开引用、应用内选中内容 | 前端按会话的 UI 状态，只存 ID/顺序等，不复制正文 |
| 对话内容与实时状态 | canonical messages query + SSE overlay，完整/紧凑对话共用 |

壳只保存它负责的状态，不镜像每个应用已经拥有的全部状态。壳展示状态采用一个互斥值表达“收起/普通/专注”，不要叠加独立的 open、maximized、focus、floating 布尔值形成非法组合。

跨应用打开命令显式接收目标 session 与资源引用。项目使用根目录和路径标识，浏览器 tab 使用 sessionID + tabID，原生产物使用其现有 ID，保存实体使用 saved ID；不能用标题作为身份。

### 7.2 必须遵守的边界

- 全部业务 API 显式传递 sessionID。资源库不能隐式读取“当前会话”来决定写入目标。
- 保持 REST/SSE/WS 和 Electron IPC 既有边界，不为布局新增后台 focus 或无 session 主路径。
- `ui_context` 继续描述用户实际查看的应用与资源；从后台工具产生的更新不能篡改可见上下文。
- UI 应用不是插件/App 包机制，不为工作区内容导航新建插件加载层。
- 不改变工具名称或 schema；若实施确需变更，同步处理 transcript 显示名与三语言文案。
- shadcn 官方组件按仓库要求引入，扩展能力放业务包装组件；加载状态继续使用统一 Spinner。

### 7.3 持久化和迁移

- 迁移前列出当前工作区、对话位置、项目标签、分栏比例等 UI key，以及收藏/关闭记录相关表。
- 原混合标签按类型拆入应用，保留同一应用内原顺序，并由原活动标签确定 activeApp；项目自己的文件标签不再复制一份。
- 已失效的运行 tab ID 不自动创建新 WebView；恢复浏览器按已有运行时生命周期处理。
- 对仍在编辑的文件和产物，先确保状态所有者稳定再移动 UI，不能用卸载重建掩盖迁移问题。
- 有效 UI 偏好做一次性版本迁移，成功后只读写新模型。旧 reader/writer、混合排序和双向同步路径随迁移删除。
- 数据表迁移与 UI 偏好迁移分开。收藏正文与 revision 不进入浏览器 localStorage。
- 数据迁移的重复执行、旧数据保留和重启结果必须有临时数据库测试；产品读取路径不长期保留两套新旧协议。

- 资源库从 + 进入及重复点击 + 都聚焦搜索。方向键选择可用结果，Enter 打开，Escape 返回搜索；不接管菜单和其他按钮的按键。搜索使用 180ms 防抖与 AbortSignal，等待新查询时保留上一批完整结果及其筛选条件，搜索框显示加载状态；删除旧的 deferred value 与加载时清空列表路径。
- 输入法组合事件提交前不请求、不触发回车打开；查询尚未完成时，键盘不能打开旧结果。专项测试使用延迟响应验证连续四次输入只发一次请求、等待期间原列表保留、旧查询取消后最新结果生效、上下键跳过失效资源、回车打开画布与清除搜索后恢复列表和焦点。组合事件自动化通过，仍不代替真实操作系统中文输入法验收。

### 2026-09-06：窗口原生手势与中文输入法

- 窗口拖动失效的根因是统一标签栏整条使用 `no-drag-region`，覆盖了外层窗口拖动区域。顶部改为 `drag-region`，每个可排序标签整体保留 `no-drag-region`；按钮沿用既有排除规则，不新增 JS 窗口拖动或双击处理。
- macOS 原生鼠标验收覆盖普通/专注模式：空白区拖动后窗口位置按手势移动、尺寸不变；双击缩放、再次双击还原；标签拖动只改变顺序；项目/画布切换、加号、专注与收起按钮可点击；无标签的资源空态顶部同样可拖动。本机系统双击标题栏偏好为 Maximize。
