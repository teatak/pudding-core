# 上下文压缩

当前实现在 `internal/engine/compact.go`、`compact_request.go` 和 `context_budget.go`。

## 触发与预算

- 保留现有手动压缩和 turn 完成后的自动压缩。自动压缩还会在每次模型请求前检查，包括队列提升后的首个请求和工具循环。
- 自动阈值由 `compact_auto_threshold_percent` 直接乘上下文窗口计算，默认 80%，不扣除模型最大输出额度或固定余量。例如窗口 1,050,000、设置 80% 时，压缩线始终为 840,000；模型支持 384K 或 1M 输出均不改变压缩线。
- 手动压缩不受自动阈值约束。有可压缩历史时执行；摘要请求仍需装进模型，但固定系统提示或工具定义超限不阻止生成摘要。生成目标只用于提示，手动结果只要求摘要完整、非空且实际投影请求缩短；即使仍超出输入预算也保留收益，下一次普通请求继续进行容量检查。
- 每次普通请求（含队列和工具循环）已填写的输出上限为 `min(配置输出上限, 窗口 − 校准后的输入估算)`，只修改当前请求，不回写模型配置。输出额度优先读取模型 limits，再读取实际协议的 options；可选输出额度未填写时保持省略，由端点决定默认行为，不自动填成整个剩余窗口。Anthropic 的 `max_tokens` 是协议必填，未配置时仍沿用适配器的 64K 默认值并收紧。输入占满窗口、没有输出空间时明确失败。摘要与标题请求保留各自的专用输出上限，摘要的独立预算见下文。
- 输入估算与 HTTP 发送共用各协议的请求组装函数，统计最终 system/messages/tools，包括原生续接推理、工具参数及协议过滤后的内容。按解码后的文本估算，媒体按图像尺寸或音频额度估算，生成参数不计入输入。UI、发送前预算、用量校准和摘要投影共用此估算。
- schema v38 只清除旧算法的 `last_estimated_input_tokens` 校准基数，保留所有实际用量与请求数；下一次真实 usage 重新建立校准，避免把旧系数乘到新口径上。
- 普通请求沿用会话、模型的实际 usage 校准系数。窗口未知时不推断硬上限。关闭自动压缩仍保留已知窗口的发送前预算检查，超限明确失败。

## 保留与摘要

- 优先保留 `compact_tail_input_turns` 指定的最近输入轮数，默认 2；预算放不下时逐步减少。
- 运行中压缩只能发生在完整工具交换已经落 canonical 的边界。即使减少到 0，仍保留当前 turn 的全部输入和最近一次完整工具交换，含并行调用、结果、附件及 provider 续接状态。保留部分本身超限时明确报错。
- 历史输入不再逐条截取前 4000 字；已有摘要的末尾、工具调用参数和消息引用会进入摘要输入。工具结果使用现有受限模型预览，精确原文仍从 canonical 历史回读。
- 每次压缩只调用模型一次，按原顺序提供完整有效历史：被替换消息标为 `action="summarize"`，近期及运行中保护的消息标为 `action="retain"`，后者供理解跨消息关系和后续纠正，继续原样保留。有效历史包含已有摘要，不重新展开全部归档消息。取消 64K 人为输入上限、分批滚动摘要和长消息切片；请求装不下时不调用模型、不提交摘要，提示选择更大窗口模型。
- 先组装完整摘要请求，再按实际协议估算 system、消息包装、用户要求和全部有效历史。估算余量为 `max(256, ceil(估算输入 × 2%))`；已知窗口下总输出上限为 `min(16384, 有效配置输出上限, 窗口 − 估算输入 − 余量)`，未配置输出上限时忽略该项。配置上限沿用普通请求的 limits／协议 options 优先级。窗口未知时仅应用配置上限及 16K 封顶，不能在本地证明完整请求能装入模型。余量是工程估计，不是精确分词保证。
- 摘要正文目标最多 4096 token，同时不超过本次替换目标及总输出预算的一半。目标改变后重新在本地估算完整请求，不发起额外模型调用。正文目标是提示约束，推理与正文仍共享模型的总输出额度；生成后不因超过提示目标丢弃结果。
- 摘要配置使用独立副本：已配置的 OpenAI 推理强度降到 low，保留更低的 none／minimal；Anthropic effort 降到 low；Google 已配置的 thinking 使用低档，并将数字预算收紧到最多 1024 及总输出的一半，保留显式关闭或更小预算。缺少推理配置时不凭协议名称添加参数，已有适配器继续负责模型档位映射。普通会话的设置和模型配置不被回写。
- 只接受正常 stop、非空且实际缩短投影请求的摘要；缺少正常结束标记、截断、调用失败及无收益均保留原上下文。自动压缩另外要求最终投影达到预算目标。没有基于报错计数的参数修正或自动重试，也不会为容量不足偷偷裁剪输入。

## 一致性与界面

- 每个会话独立互斥。最终事务同时校验历史末条消息 ID 和运行中 turn 的所有者；压缩期间历史改变则拒绝提交，避免摘要吞掉新消息。
- 仅最终验证通过的摘要成为 canonical 压缩边界。原始消息不删，沿用现有 metadata 和历史检索，不新增数据库表结构或第二事实源。`metadata.compact` 的可选 `before_input_estimate`、`after_input_estimate` 和 `input_budget` 记录该次操作校准后的估算输入量及当时预算；旧消息缺少这些字段时仅展示原有历史条数。
- 压缩成功后工具循环清空旧请求累积，从 canonical 重新构建；压缩期间收到的 steer 在下一次普通模型请求前应用。
- 运行中摘要归属于当前 turn，按 turn_index 插入工具步骤之间，发送持久化的 `turn.compacted` 事件，不结束 turn。界面刷新 canonical turn 并按工具调用 ID 去除重复的旧流式前缀；摘要正文不进 overlay。手动压缩继续使用独立 turn。
- 压缩卡片与工具卡片共用 `TranscriptDisclosure` 的 24px 折叠行高，无额外上下 margin；展开后显示摘要内容。
- 成功卡片显示估算节省量和比例，展开可看前后估算值与摘要；仍超限的结果显示“已压缩，但仍超过上下文上限”。这些信息来自 canonical metadata，刷新后保留，数值描述压缩时的状态。
- 手动请求失败时原卡片保留同一个 key，原位显示错误，详情默认折叠；未减少上下文显示“未获得压缩收益”，空摘要及未完整生成显示各自原因。容量不足和截断同时返回稳定错误码及具体 detail；前端展示 HTTP 状态、说明及原始原因。错误不再占据输入框上方。该请求状态留在页面 overlay，重试替换本次操作状态，不会作为摘要写入上下文。
- 手动提交与普通发送共用贴底信号；压缩期间主动上滚仍可阅读历史。没有流式输出的完成事件仅触发 canonical 刷新，不创建空助手行；纯压缩卡片不保留空的消息元信息容器，等待和成功状态的整行高度均为 24px，避免结果到达时临时增加间距。
- 请求日志记录摘要输入估算、实际输出上限和窗口，失败日志记录错误分类，不记录历史正文。成功日志记录 `beforeInputEstimate`、`afterInputEstimate`、来源消息数和保留消息数。Responses 截断响应若提供 usage，仍记录实际用量；估算值不等于模型实际计费量。

## 回归入口

- `make test`：含并发快照、持久化重启、超长摘要输入、长 tail、工具循环续接、取消、独立会话和输出截断回归。
- `npm --prefix web test`、`npm --prefix web run build`。
- 桌面：先构建当前 daemon，然后以 `PUDDING_DAEMON_BIN=<绝对路径> PUDDING_SMOKE_SCENARIO=context-compaction` 运行 `web/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron electron/smoke/workspace-dev-smoke.cjs`。测试使用临时 home、随机端口、本机模拟模型，验证运行中压缩后仍能停止任务。

回归验证边界和续接，不代表真实模型摘要的信息保留质量；单次摘要仍是有损转换，需通过真实任务另行评估。

2026-09-14 验证：`make test`、压缩相关 race 检测、67 项 Web 测试、前端构建及 218 项 Electron 测试通过。隔离桌面使用本机模拟模型，7 次工具交换后从 28,585 降至 8,056 个估算输入 token；确认原始记录保留、同一 turn 内展示、取消及刷新恢复。工具与压缩行均为 24px；手动压缩失败保留原 DOM 节点，垂直位移不超过 1px，详情在卡片内展开。
