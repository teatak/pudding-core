# 当前会话内的子会话协作：设计与实施计划

> 日期：2026-09-21。状态：首版开发及本地验收完成，尚未发布。
> 本文是跨仓唯一实施文档：core 负责关系、调度、权限与协议；desktop 负责会话和工作区交互。
> `internal/`、`contracts/` 相对 pudding-core；`web/`、`electron/` 相对 pudding-desktop。
> 以下记录首版行为及边界；验证范围和实施记录见第 9 节。

## 1. 目标与范围

主会话可以把明确的工作交给子会话，跟踪执行、收回结果并完成整合。用户始终在现有会话界面操作。

首版采用一层父子关系、有限并发。子会话是普通 Session，拥有独立 canonical messages、Turn、工具执行、SSE 和输入队列；归属关系由后端保存。

本功能不增加会话模式、独立协作页面或左侧子会话入口。定时执行、持续任务、外部 A2A、递归派发、自动合并 worktree、daemon 重启后恢复原工具调用栈不在本次范围。

[任务设计](tasks-design.md) 中的任务页、定时器和外部 callback 属于另一项规划，不能套用为本功能的交互或实施前置条件。

## 2. 已确定的交互

### 2.1 底部子任务组件

- 复用现有输入框上方的步骤入口，同一轮只有一个步骤／子任务组件。
- 收起时显示子任务数量、进度摘要及需要关注的状态。
- 点击摘要向上展开任务行；卡片相对输入框居中，左右按吉祥物的实际占位等距横向留空；不通过增加上下间距避让。任务行的对话图标与标题同一行居中对齐，下方展示来自真实输入的说明，右侧展示状态。底栏和展开列表属于一个常驻卡片，不使用弹窗、Portal 或点击外部关闭机制；输入框不随展开上下移动。
- 每行显示任务名称、必要的当前动作、状态；点击子任务，在右侧工作区打开对应会话。
- 执行进度直接显示在这些任务行中，不再追加独立进度卡片，也不在主消息流增加“调度子会话”时间线。
- “停止协作”放在卡片底栏右侧，左侧统一展示子任务完成数、待审批数和展开／收起按钮；会话顶部和右侧子会话不重复提供全局停止入口。
- 主会话自己执行的步骤可以显示在同一列表，但不能伪装成子会话或打开虚构会话。
- 没有子任务时保持现有步骤行为；历史协作仍可从其主会话查看，不制造多个同时悬浮的进度面板。

### 2.2 右侧完整子会话

- 点击任务打开现有右侧工作区中的会话视图，复用 Transcript、Composer、工具折叠、消息分页、流式输出和重试能力。
- 子会话不显示吉祥物；吉祥物仅保留在主会话。
- 展示真实的派发消息、完整执行消息、工具调用及结果；支持给该子会话直接补充要求。
- 输入明确发送给当前子会话，运行中沿用现有 steer／排队语义，不隐式发送给主会话。
- 展示所属主会话和当前子任务名称。切换子会话时保留各自草稿和滚动位置。
- 关闭右侧面板仅改变本地展示，不取消任务；重新打开读取同一 Session 的消息与实时 overlay。
- 不将子会话加入左侧普通、置顶或归档会话列表。全局搜索若命中子会话，必须定位到所属主会话并打开右侧；该路由完成前不把子会话作为普通搜索结果暴露。

### 2.3 审批与补充输入

- 所有操作审批统一出现在主会话现有审批区，显示来源子会话、目标资源和授权范围。
- 审批对象始终保留真实的 `sessionID / turnID / approvalID`；点击批准或拒绝仍操作原始子会话请求。
- 右侧只显示等待审批状态和返回主审批区的定位入口，不渲染批准／拒绝按钮。
- 多项审批按稳定顺序排队，可以逐项查看；不能因切换右侧会话、折叠卡片或刷新而丢失请求。
- 一次批准不能扩大为整个协作组的授权。主模型不能代用户批准新的权限。
- 现有 `request_user_input` 在主窗口显示来源并依次答复；右侧仅提示返回主窗口。答复仍路由到原子会话的真实请求，问题和操作审批保持各自语义。停止协作时收起本次被停止任务的问题，保留 canonical 工具记录供用户显式重新打开。
- 子会话新增要求、重试或重新执行后，主会话必须获知结果版本变化，不能验收旧结果。

## 3. 当前代码基线

### 能力入口：内置“协作”App

已确认选型（2026-09-21）：通过 daemon 常驻的内置 App 提供协作工具，ID `collaboration`、名称“协作”，最低模式为 Work。直接复用现有 Apps 管理页、`enabled` 配置及会话按需加载流程；不把派发能力加入所有会话常驻的 Core 工具集合。

统一命名：

| 字段 | 定义 |
| --- | --- |
| 中文名称 | 协作 |
| 英文名称 | Collaboration |
| 稳定 App ID | `collaboration` |
| 中文简介 | 让主会话分派子任务、跟踪执行并汇总结果。 |
| 英文简介 | Let the main conversation delegate subtasks, track their progress, and bring results together. |

Apps 列表、详情页、按需加载说明和 i18n 使用以上命名。底部入口继续使用“子任务”，停止操作使用“停止协作”；右侧标题使用具体子任务名称。

该选型沿用 [内置 App 设计](builtin-apps-design.md)：

- 用户在“应用 → 协作”切换全局启用状态；配置唯一来源仍是 `<home>/config/settings.yaml` 中的 App enablement。
- App 启用、主会话已加载、模式满足要求且当前 Session 是主会话，派发工具才可见、可调用。开启 App 不代表自动创建子任务，也不授予额外权限。
- 关闭后从模型可见 App 索引与后续工具 schema 中撤下；执行入口也重新检查开关，拒绝迟到的模型调用及新的派发请求，不能仅隐藏 UI。
- 关闭 App 保持已有 App 的生命周期语义：已接受的子任务继续执行，已进入的等待和结果回收可以正常收尾；不会强制终止已启动资源，也不删除历史会话。
- 结果回收与中断处理属于 engine 生命周期，不能依赖关闭后再次调用 App 工具或重新加载 App；主会话仍能收到已派发任务的结果。
- 用户要立即结束当前协作，使用底部组件内的“停止协作”。查看历史、右侧会话输入、主窗口审批和停止操作，在 App 关闭后仍可用。
- 重新启用允许后续派发，不自动重启已取消任务；内置 App 可关闭、不可卸载。
- `loadedAppIDs` 是按需加载状态，不是另一份用户禁用设置。首版不添加独立会话总开关；子会话无论 App 是否启用均不能递归派发。

首版默认启用但按需加载。App registry、Skill 说明、工具归属与后端开关校验均已接入。

App 只承载能力入口及工具说明。底部子任务组件、右侧完整会话和主审批区继续属于现有会话界面；不在 App 详情页另建协作工作台。

## 4. 数据和事实源

### 4.1 父子关系

首批增加 `session_children(child_session_id, parent_session_id)`。每个子会话仅有一个父会话，关系创建后不可更改；两端必须是真实 Session，不能自指或递归派发。

创建子会话与关系必须在一个事务中完成；不能先创建普通会话，再由 UI 将它隐藏。模型、项目等仍保存在子会话自己的 Session 中，关系表不复制消息、状态或配置。

默认会话列表只返回主会话；内部维护必须显式读取包括子会话的全部会话。按父 ID 读取子会话时验证父资源存在；子会话可继续使用显式 Session API 获取自己的消息和执行状态。

存储层 `ListChildSessions` 包含已归档子会话，供整组生命周期操作使用；不存在的父资源返回 not found，存在但没有子会话的父资源返回空列表。此查询不能代替 API 的访问范围校验。

`session_dispatches` 在提交事务中保存派发输入及来源 Turn / tool call 关联，确定重复派发的幂等身份；不允许“关系创建成功、派发请求永久丢失”的中间状态对外宣称执行成功。不得为了重试复制另一份对话历史。

### 4.2 状态与结果

- 排队、运行、失败、取消来自已有 queued inputs 和 turns。
- 待审批、待用户输入来自各自原始请求；子任务组件只做聚合展示。
- 模型 Turn 结束表示本次输出结束，不等于主会话验收通过。
- 结果记录引用明确的子会话 Turn 和 canonical message，区分“结果已提交”和“主会话已处理”。
- 主会话收回结果、用户向子会话追加输入、子会话重试都绑定具体轮次；旧结果不能覆盖新结果。
- 仅为了显示计数，不新增一份可写的进度／状态表，也不让 Zustand 成为协作事实源。

### 4.3 生命周期

删除父会话时，后端先取消并释放父子运行资源，再原子删除父子持久化数据；不能留下自动变成普通会话的孤立子会话。归档、恢复及过期清理以整个会话组为边界。

附件、浏览器、后台进程和产物仍按真实 Session 归属；级联删除数据库记录不能替代资源释放。项目授权撤销和 App 卸载等内部维护必须遍历子会话。

## 5. 调度、取消与资源约束

### 5.1 派发与回收

1. 主模型按需加载已启用的“协作”内置 App，通过其工具派发任务，明确目标、输入和验收条件。
2. engine 校验父子边界、能力范围和并发上限，持久化派发，然后启动子会话。
3. 主会话可继续处理独立工作，或通过等待工具让程序等待子会话事件；等待不靠反复调用模型轮询。
4. 子会话提交输出后，engine 通过持久化轮次和消息引用回收结果；主模型判断是否整合、补充要求或重试。
5. 主会话最终向用户交付汇总及验证结果。子会话全文保留在右侧，不自动逐条复制进主消息流。

已交付四个工具：`builtin_collaboration_dispatch(title, prompt)`、`builtin_collaboration_send(session_id, prompt)`、`builtin_collaboration_wait()`、`builtin_collaboration_stop()`。工具名称包含简中、繁中和英文显示文案。

### 5.2 停止语义

- “停止协作”取消当前协作中的排队和运行子任务，使等待中的主会话收到取消结果；主会话仍可继续沟通、处理已取得的结果。
- 当前协作停止后，迟到的派发和旧等待回调不能重新启动子任务；用户明确发起的新一轮工作可以创建新协作。
- 主会话自身的取消操作同时取消它正在管理的子任务。
- 取消可重复调用，已完成结果保留。取消与完成竞态由持久化收尾决定，不能由最后一个前端事件覆盖。
- daemon 重启后中断的执行如实显示失败／中断，保留消息和已有结果；允许显式重试，不承诺自动续跑。

### 5.3 权限与并发

- 首版只允许单层派发；每个主会话最多 3 个子会话同时执行，由 engine 的单一常量定义，首版不提供额外设置项。
- 子会话不因父子关系自动获得新的目录、应用、浏览器或桌面权限。已批准能力的复用必须遵循其原始范围和有效期。
- 同项目工具写操作和无法确定副作用的命令串行执行；并发模型推理不等于可以同时改同一文件。
- 桌面键鼠等机器资源按 daemon 互斥管理；浏览器与其他 Session 资源保持其现有归属。
- 长命令和后台进程的资源占用持续到其真正退出或释放，不能在工具返回句柄时提前解除占用。
- 隔离工作目录、自动合并结果是后续扩展，首版不能把提示词“不要冲突”当作隔离机制。

## 6. API、事件和桌面接入

新增接口全部位于 `/sessions/{parentID}/…` 范围内，包括子任务快照和停止协作。子会话消息、输入、取消、重试仍复用自身 `/sessions/{childID}/…` 端点，不增加全局 current session。

父会话事件用于通知子任务集合或结果引用发生变化，子会话事件继续承载它自己的执行流。持久化 lifecycle 事件沿用单调 seq、`Last-Event-ID` 和快照对账；不得通过父 SSE 复制子会话所有 token。

审批聚合接口／客户端读取必须覆盖未打开的子会话。事件断线后先恢复真实快照，再按原身份处理请求；失效审批不保留可点击按钮。

子任务卡片及审批读取后端快照；只有右侧当前展示的子会话订阅自己的 SSE，切回标签时刷新 canonical turns。侧栏只订阅列表中的主会话，不从子会话 overlay 重复建立连接，历史子任务也不占用长连接。

desktop 的 Router 仍定位主会话；右侧当前子会话是本地工作区选择。Query 保存服务端快照，Zustand 保存实时 overlay 和展示状态；嵌入的会话组件显式接受 `sessionID` 与审批展示位置，不能依赖全局选中 Session。

协议变化统一修改 core `contracts/`，desktop 从准确 core revision 生成契约并更新 `core.lock.json`。禁止手改生成文件，禁止 core 构建读取 sibling desktop。

## 7. 验收条件

- [x] 主会话能派发两个独立子任务，收到各自结果并完成整合。
- [x] 左侧普通／置顶／归档列表不出现子会话；内部授权撤销与清理仍覆盖它们。
- [x] 底部只有一个步骤／子任务入口，向上展开，输入框不移动，无重复调度时间线。
- [x] 点击行打开右侧真实完整会话；输入、流式输出、工具折叠、历史分页、重试和草稿互不串线。
- [x] 关闭右侧不停止任务；刷新可恢复关系、消息、当前状态和未决审批。
- [x] 子会话审批只在主会话处理，批准／拒绝命中原 Session；同时出现多项请求也不丢失。
- [x] 子会话追加要求后主会话可以获知新版本，不能把旧交付误认为最新结果。
- [x] 停止协作取消运行与排队任务，释放等待及资源，主会话仍可继续；重复停止和完成竞态正确。
- [x] 不允许自指、跨父访问、递归派发、通过重新绑定获取权限或重复派发产生重复子会话。
- [x] 关闭“协作”App 后不再接受新派发，包括迟到的工具调用；已派发任务可收尾，结果回收、审批、历史查看和停止仍可用。重新启用不自动重启已取消任务。
- [x] 同项目写冲突、桌面资源争用、后台进程、父会话删除／归档都有明确且经过测试的行为。
- [x] daemon 重启后显示真实中断状态；旧数据迁移保留消息，迁移失败回滚，重启后关系不丢失。

### 2026-09-21：M2–M4 首版完成

- 新增 schema v22：`session_dispatches` 保存工具派发身份，`collaboration_stops` 保存当前父轮次的停止屏障。关系、派发来源和首次输入同一事务落库；不另建进度事实表。
- 结果以父会话 canonical `collaboration_result` 消息保存，包含子会话和子轮次身份，并兼作幂等回执；只回收最新已结束且无后续排队输入的轮次。在模型工具边界回收，不拆开 tool call / result；主会话已结束时可由新结果触发一次幂等继续。
- 默认启用的“协作 / Collaboration”App、四个工具、Work 门槛、按需加载和执行时开关检查已实现。关闭 App 不影响已接受任务和结果回收；子会话无法加载协作工具。
- 并发 admission、排队提升与停止共用 engine 调度锁；同项目工具写入与命令持有资源锁，后台命令退出后才释放。原生桌面互斥复用 `computer.Manager`。
- 归档／删除先关闭新输入和新派发入口，再取消并释放整组运行资源。保留已有重启失败收尾语义，不恢复旧工具调用栈。
- 新增 `GET /sessions/{id}/children`、`POST /sessions/{id}/collaboration/stop` 和持久化 `collaboration.changed`。主会话审批快照按创建时间和 ID 排序，保留子会话原始身份并带 `sourceTitle`。
- desktop 复用底部步骤组件向上展开子任务，点击在现有右侧工作区打开完整会话；审批只在主输入区操作。子会话支持独立草稿、搜索、补充输入、流式输出、历史、重试，以及自身产物预览和返回。卡片按确认稿改为常驻任务列表与统一底栏，向上在原位展开，左右等距留白、横向避让吉祥物，末项与底栏保留分割线；App 和子任务采用双对话气泡图标。子会话不进入左侧列表或全局普通搜索候选。
- 实测发现重试分页会返回整条重试链，已修复快照和结果唤醒读取旧轮次的问题，并增加 SQLite / memstore 回归测试。失败／取消状态不会被“结果已回收”覆盖。

### 2026-09-21：整体复查

- 实际复现三个子任务同时执行时，主会话与侧栏重复订阅子 SSE，耗尽浏览器 HTTP 连接，审批按钮持续等待。已移除重复订阅，并限制子会话实时流为当前展示标签；审批与任务状态由快照覆盖未打开的子会话。

- 隔离 Electron 已重新验证依次批准／拒绝两项审批、未打开子会话时出现问题、主窗口答复、子会话完整记录、停止等待任务，以及隐藏子标签更新后重新打开读取最新消息。后端协作／审批／存储相关竞争检测回归通过。
