# Browser remote access

The browser client shares the desktop session and business API. Electron owns LAN HTTPS and relay connections; the Go daemon binds loopback and requires its startup token on every `/remote` route. A phone credential never replaces this startup token.

SQLite schema v31 owns a random stable `desktopID`, pairing state, and device authorization. Identity follows the daemon data home (`~/.pudding-dev` or release `~/.pudding`); relay registration uses that ID and does not own identity. Provider YAML remains the source for `/remote/models`, which returns only configured provider/model IDs and labels, omitting unavailable models and all secrets.

1. Desktop creates a pairing via `POST /remote/pairings {mode,origin}`. The eight-character Base32 code is returned once; only SHA-256 is stored. It expires after five minutes.
2. Browser sends code/name to gateway, which injects its exact HTTPS origin and `lan` or `relay` mode before forwarding `POST /remote/pairings/request`. The code is consumed atomically; request returns an opaque poll token (stored only as a hash).
3. Desktop approves the requested pairing at `/remote/pairings/{id}/approve`, or denies/cancels it. Poll remains pending until approval. The original five-minute expiry still applies.
4. Approved `/remote/pairings/{id}/poll` creates the device and consumes the pairing in one transaction. A 30-day token is returned exactly once, and its hash is the only durable credential. Losing the response requires pairing again. Gateway stores the token in a host-specific HttpOnly Secure SameSite cookie and removes it from the public response.
5. Gateway authenticates every request through `POST /remote/authorize {token,mode,origin}` and applies its explicit owner-business allowlist. Wrong host/mode, expired and revoked tokens return 401. Device deletion immediately invalidates authentication.

`GET /remote/access` exposes active devices and unexpired pairings, with RFC3339 timestamps and non-null arrays. Pairing statuses are `pending` (code unclaimed), `requested` (awaiting desktop approval), or `approved` (awaiting credential claim). Public poll statuses are only `pending` or `approved`; unavailable, consumed, denied or expired poll credentials return 401 `remote_unauthorized`. Invalid scope/name returns 400; approval in a wrong/expired state returns 409. Scope origins are exact HTTPS origins without a trailing slash.

`GET /remote/events` is a startup-guarded resource authentication invalidation stream. It starts with `remote.ready {}`, followed by `remote.changed {deviceID?,pairingID?}` after successful mutations. It is not conversation history, has no resumable sequence and owns no credential facts. On connect/reconnect the gateway reauthorizes its active streams; on changed events it rechecks affected authorization and closes revoked streams. Slow subscribers disconnect rather than miss invalidations. Expiry is also enforced from the canonical credential timestamp by the gateway's stream lifetime and the daemon on each authorize request. Session SSE retains its existing sequence/replay semantics.
