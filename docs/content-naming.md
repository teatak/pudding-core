# Content naming

Updated 2026-10-16. This is an internal source refactor, with no protocol or database migration.

| Product | Internal root | Store model and methods | AI tools |
| --- | --- | --- | --- |
| Notes / 笔记 | `note` / `Note` | `NoteContent`, `NoteWrite`, `CreateNote`, `GetNote`, `WriteNote` | `builtin_note_create/read/edit` |
| Documents / 文档 | `document` / `Document` | `DocumentBody`, `DocumentNode`, `DocumentWrite`, `CreateDocument`, `GetDocument`, `WriteDocument` | `builtin_document_create/read/edit` |
| Shared content | `content` / `Content` | `ContentSnapshot`, `ContentAuthor`, `ContentHash`, `ContentConflict`, `InvalidContent` | `builtin_artifact_list/open` |

Plugin/Skill display names are Note Authoring and Document Authoring. Their internal constants are `BuiltinNoteAuthoringID` and `BuiltinDocumentAuthoringID`; their persisted values remain `markdown` and `docx`. Model-facing instructions remain English.

## Source layout

- `internal/store/note*.go`: Markdown bodies, exact text edits, range leases and selective undo.
- `internal/store/document*.go`: structured bodies, nodes, layout, header/footer, assets, block operations and selective undo.
- `internal/store/content.go`: shared snapshot envelope, authorship, hashes and errors. `NoteContent` aliases the string snapshot; Documents and tables decode the snapshot body as JSON into their own models.
- `internal/store/sqlitestore/notes.go`, `note_edit_operations.go`: note persistence and leases.
- `internal/store/sqlitestore/documents.go`, `document_migration.go`: structured document persistence and the existing kind migration.
- `internal/store/sqlitestore/native_content.go`: shared snapshot scanning and revision persistence. `nativeContentSave` contains persistence metadata only; it is never used to fingerprint an editor request.
- `internal/api/notes.go`, `documents.go`: HTTP handlers; `native_content.go` holds shared request decoding and metadata helpers.
- `internal/tool/note.go`, `document.go`: independent tool definitions. `studio.go` assembles the catalog and keeps the existing shared argument decoder for notes, tables and list/open.
- `internal/engine/note.go`, `document.go`: execution paths. `studio.go` dispatches and maps common errors.
- `internal/plugin/builtin_note.go`, `builtin_document.go`: the independent authoring instructions.

Use snake_case filenames and Go naming conventions. Markdown and DOCX remain format names (`DOCXMIME`, file extensions and conversion instructions). LSP documents are source-code documents and retain their own terminology.

## Compatibility boundary

The following are identities or serialized contracts, not product names:

| Boundary | Preserved value |
| --- | --- |
| Stored kinds | `StudioItemKindNote = "note"`, `StudioItemKindDocument = "document"` (migrated from `doc` and `rich-document` in schema v41) |
| Content IDs and references | `doc_…`, `rich_…`, `@note` (with backward-compatible parsing for historical `@doc`, `kind="doc"` and `kind="rich-document"`) |
| Plugin and Skill IDs | `markdown`, `docx`; existing enablement and session loading |
| HTTP | `/content`, `/edit-operations`, `/assets`, `/document-content`, `/document-assets` |
| Wire errors | Including `document_locked` and `content_conflict` |
| Public TypeScript contracts | Existing `DocumentContent` (Notes), `RichDocumentContent` (Documents), schema names and JSON keys |
| Limits contract | Existing `maxDocumentBytes` / `MaxDocumentBytes`, `maxDocumentEdits` / `MaxDocumentEdits` for Notes |
| SQLite | Existing tables, columns, kind constraints, schema version and migration SQL, including `studio_rich_blobs` |
| History and retry identity | Original tool names, snapshot bytes, hashes, author fields, request fingerprints and revision IDs |

Internal Go types are renamed directly, without compatibility aliases: they are not a public Go API. Do not copy their new names into wire fields or published TypeScript schemas. In particular, do not embed/reorder fields in write-request structs: their serialized bytes participate in retry fingerprints. Shared save metadata is constructed only after hashing the original request.

The exact legacy `builtin_doc_*` aliases and six-month retirement record remain in [Studio](studio.md#tool-names-and-legacy-doc-retirement). This refactor adds no tool aliases and never rewrites canonical history.

## Regression evidence

`internal/store/sqlitestore/testdata/content_naming_legacy.{sql,json}` was generated by the implementation before this internal rename. Keep these fixtures frozen. `TestContentNamingPreservesHistoricalStorageAndRetries` reopens their note/document snapshots, replays old save requests without new revisions, compares serialized responses and checks historical body hashes, assets and kind isolation.

Existing API, lease/restart, selective undo, migration, tool routing, independent plugin loading and provider-history projection tests remain applicable. No database upgrade or protocol version bump is needed.
