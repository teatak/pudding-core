## 范围与方法

使用官方 DeepSeek Flash Chat Completions、reasoning_effort=high、输出配置 4096。模型参数、工具白名单及业务执行路径保持一致，唯一实验开关是 `experimental_tool_result_memo`，开启时使用 `summarize-results-v1`。任务提示不提及或要求整理控制。

四个任务来自当前 Core／Desktop 工作区的真实实现及测试：草稿重启恢复（7 文件／1108 行）、附件上传与发送确认（8 文件／1153 行）、Widget 安装升级（8 文件／1308 行）、历史结果回读（6 文件／1546 行）。它们是基于真实源码设计的只读审查任务，不是生产事故复现或无人值守修复任务。每个任务都需要跨文件判断；当前工具只允许读取冻结清单中的项目文件和本会话历史结果。

源码包含未提交内容；用户明确批准发送这四组快照后才调用 DeepSeek。文件内容和哈希事先冻结，评分答案只保存在宿主清单，不进入模型项目。每对采用同一输入及新建临时 SQLite；运行顺序为关→开、开→关、关→开、开→关。使用冻结二进制，不为好看的答案重跑样本。

每个任务有 9 项预先确定的事实问题，答案和引用分别评分。引用检查要求每项至少有一处允许来源内、准确行范围中的原文片段；它不自动证明所有解释均正确，解释另作人工核对。JSON 格式错误、事实错误、引用错误和运行失败分别报告。

每条主任务后附一个不要求整理的证据细节追问，随后模型可按需要回读原工具结果。此前将临时源码副本改写，确保回读的是保存的原始证据；用户工作区没有改动。追问最多 4 次请求，主任务最多 24 次；工具读取、回读、失败请求和推理输出均计入统计。

费用按 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/) 的统一峰时费率估算：USD/百万 token，未缓存输入 0.30、缓存输入 0.006、含推理的输出 1.20。此费率于本次评测时核对；离峰费率减半。完整用量按每次 HTTP 返回的 usage 加总，并与 SQLite 持久计量核对。这是统一费率比较，不是账户账单；缓存状态实际观测、未被强制控制。

HTTP 超时且没有 usage 的请求不能算成零成本；对应链的费用只能报告已知下界，不能与完整任务直接计算增减比例。结果不会因失败而从原始记录中删除。
