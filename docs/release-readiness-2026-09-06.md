## 本轮发现与修复

资源库搜索对已关闭画布去重时，仅使用 `itemID`。当另一会话的最近记录包含相同 ID，当前会话的已关闭画布会被错误隐藏。

- 修复：只有当前会话的最近画布参与其已关闭画布去重。
- 文件：`web/src/components/workspace/WorkspaceLibrary.tsx`。
- 证据：真实 Electron/Vite/daemon 测试创建两个会话的同 ID 画布。修复前断言失败，修复后两个结果均可见。
- 回归：`electron/smoke/workspace-dev-smoke.cjs` 的 `library-search` 场景。

## 升级与数据

本版 SQLite 从 v13 **一次迁移到 v17**，不能沿用 0.2.11“无数据迁移”的发布说明。原未发布的 v14/v15/v16/v17 四步已经合并为一条目标为 v17 的事务：直接生成最终收藏及最近打开结构，不再创建文件收藏中间表。迁移执行器按已登记版本排序，已发布的 v1–v13 路径保持不变；现有 v17 开发库重开不重复迁移。未发布中间版本 v14–v16 不再作为升级入口，遇到时直接报不支持并保留原库。

除已有迁移、保留和回滚测试外，本轮直接读取 `v0.2.11` tag 的真实 `schema.sql`，在临时数据库插入虚构数据，再用当前 Store 打开升级。16 项内容与完整性检查通过：项目、会话、turn、canonical message、应用授权、浏览历史、浏览器标签、工作画布、收藏内容和 revision 等保持正确。已关闭画布转入保留内容并保持初始关闭状态；已有保存版本迁为收藏；不伪造最近打开时间。

同时验证了升级前 v13 备份及其中的原关闭快照、数据库完整性、外键，以及重启后不重复迁移。临时验证程序与数据已清理，未读写用户正式数据库。

合并后已加入永久回归夹具 `internal/store/sqlitestore/testdata/schema-v13.sql`（来自正式版 tag，校验原始指纹）及 `workspace_migration_test.go`。注入后段 SQL 失败时，旧实现复现停在 v15；合并后的整条事务回滚至 v13，关闭快照与正文保持原状，移除故障后重试可正常升级。另覆盖备份、完整性、重复启动、现有 v17 收藏与历史保留，并删除原中间版本的迁移与测试路径。

合并完成后重新执行 Go 全量测试（含 schema 发布契约检查）、SQLite 全量测试及 SQLite race 检查，全部通过。本次仅修改迁移和相应测试、文档，未重复前端或桌面交互验收。

旧程序不支持 v17 数据库。若发布后需要降级，必须按迁移前备份恢复流程处理，不能直接让旧版打开升级后的数据库。

## 内存评估

环境：macOS arm64、16 GiB RAM、Electron 43.2.0，当前源码 Vite/daemon，临时数据目录。页面为 20 个本地 HTML，每页 300 行文本及一个输入框。

| 状态 | 网页 guest 进程数 | guest 工作集合计 |
| --- | ---: | ---: |
| 1 个网页 | 1 | 97 MiB |
| 8 个网页 | 8 | 775 MiB |
| 20 个网页 | 20 | 1,760 MiB |
| 全部关闭 | 0 | 0 MiB |

全部关闭后 guest 均销毁，容量可再次使用。上限为每会话 20、全局 40；本轮实测 20 个，并未实测全局 40 个。

以上是 Electron 按 PID 汇总的工作集，共享页可能重复计数，不是净物理内存。测试环境总工作集含 Vite，不能作为正式安装包占用；复杂网站也可能明显更高。后续可评估后台标签休眠，本轮没有为此引入新机制。
