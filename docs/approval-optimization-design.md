# Code 审批优化方案：减少无谓确认

> 更新：2026-09-20。状态：Auto 已改为授权项目沙箱内自主执行，动态语法不再单独触发确认；保留已识别风险、扩权审批及固定命令会话复用。其余分期目标未实施。
> 规划核对基线：`c42eb7d7`。当前优先减少命令执行误报，不引入额外 LLM 自动审核；目录合并审批暂缓。
> 用户目标：最大限度减少无谓审批，同时保留真正的越权、高风险操作确认。

## 本次实现范围

- Auto 新增普通 HTTP/HTTPS 下载豁免：单 URL、无账号凭据/上传/请求体/自定义方法，支持明确的输出路径和少量完整识别的选项。外部下载要求 `curl -q`（首参数）或 `wget --no-config -O <文件>`，避免默认配置暗含上传或认证；输出路径参与项目边界检查。未知选项、复合下载后执行仍审批，不宣称 GET 永远无服务器副作用。
- Auto 在既有项目沙箱内默认允许复杂命令：动态列表、嵌套循环、函数、变量、重定向和未知脚本不因无法证明只读而单独审批。AST 只检查已识别风险、路径和敏感环境；字面量 Shell/eval 内容有界检查，运行文本不变。未知文件访问由 OS 沙箱及其子进程继承机制约束。删除先前只读循环展开及语法豁免机制，不再发出 `dynamic_command` 原因。
- 此改变明确接受项目内代码执行风险，不保证阻止任意脚本删除项目或外发数据；项目可写、网络可出站的现有能力不变。Ask 仍确认命令，host 仍需独立授权，运行期拒绝不自动扩权或整段重试。未实现新的网络权限/目录授权模型。
- Ask/Full 默认语义、目录权限与 host 单次审批不变。固定、前台、非交互、字面量开发命令可明确选择 session 复用；必须先通过现有低风险分类，只额外接受项目内已存在目录的 `PYTHONPATH` / `VIRTUAL_ENV`。因此 Auto 下这类环境配置不再每次重复问。动态 Shell、复合命令、重定向、PATH/NODE_OPTIONS 等环境覆盖、高风险命令与任意 host 脚本不提供普通复用。
- 授权绑定程序身份、完整参数、cwd、环境、项目及规范化目录边界；程序不得位于项目可写目录。执行前复核并使用绑定的字面量 argv/环境，沙箱授权始终走原沙箱 runner。Chrome 特例沿用相同授权存储，只允许其既定截图名/尺寸变化。
- 审批卡显示后端分类原因；会话菜单「命令授权」从后端读取本次启动内的授权数、原因计数与复用次数，可撤销整个会话的命令授权。一次请求可计入多个原因，不记录环境值或额外调用审核模型。撤销、项目移动/合并、roots/审批模式变化、会话释放和重启均失效；撤销也使待处理确认失效，不终止已运行进程。
- 尚未实施：真正的 turn 复用、`call` scope 迁移、审批归并、目录权限模型调整。当前工具审批 API 的 `turn` 仍表示仅本次，UI 明确显示「允许本次」。下文未在本节声明交付的内容仍为规划。
- 全部判定在本地规则中完成，不额外调用审核模型；`file_patch` 严格校验保持不变。

## 1. 交付目标与不做的事

首期必须直接改善日常 Code 工作流，不能先交付更多限制、把减少弹窗留给后续阶段。

- Auto 下已授权项目内的常规检索、编辑、测试、构建和依赖安装保持可自动进行。
- 不因调用的是 Shell、有多个命令、程序名称不熟悉或需要正常下载，就机械增加审批。
- 同一已批准用途、执行边界和有效期限内，符合明确复用规则的操作不再询问。
- 同一次调用的目录扩展、操作风险和 host 需求，在条件明确时合并为一张卡。
- 高风险操作仍展示具体对象；批准普通命令不等于授予 host，也不改变项目审批模式。
- 手动点击 Markdown 文件链接走用户打开入口，不触发 LLM 命令审批，见[链接方案](https://github.com/teatak/pudding-desktop/blob/main/docs/local-html-preview-and-links-design.md)。

本轮不做：默认原项目只读、默认全局禁网、隔离副本/worktree、Task/Run 系统、替换沙箱运行时、freeform 或强制 executable + argv 改造。这些不是降低重复审批的前提。`file_patch` 的严格行号、内容匹配及漂移校验保持不变。

## 3. 哪些直接过，哪些仍要问

以下是目标行为；同一操作仍须先满足有效资源范围。

| 场景 | Ask | Auto |
| --- | --- | --- |
| 文件读取、搜索、结构化 Git 查询 | 不弹 | 不弹 |
| 已验证的只读 CLI，例如受限参数的 `rg`、`ls`、`git status` | 不弹 | 不弹 |
| 常规结构化文件编辑、严格 Patch、已支持的本地 Git stage/unstage/commit | 按现有写入确认 | 不增加审批，保留各自校验 |
| 项目内常规测试、构建、依赖安装、开发服务 | 本次确认；符合规则时可选择复用 | 保持现有可自动执行范围 |
| 可完整识别的普通 HTTP/HTTPS 下载，无凭据、上传或执行下载内容 | 按普通命令确认，可选择复用 | 不仅因外部 URL 再审批，校验参数和写入位置 |
| 已能可靠分析的管道、重定向、复合命令 | 按各段实际操作判断 | 按各段实际操作判断，不因组合形式多问一次 |
| 新的项目外目录访问 | 确认新增范围；已授权范围不重复问 | 同左 |
| 确需 host 服务的命令 | 确认本次，或使用明确获批的专项复用规则 | 同左 |
| 删除用户数据、强制覆盖 Git 历史、发布/推送、凭据及系统设置操作 | 确认具体操作，不用普通复用授权覆盖 | 同左 |
| 无法可靠判定的展开或脚本行为 | 命令执行仍确认 | 在已授权沙箱内执行；不声称只读，不因语法未知多问一次，已识别风险仍确认 |

Full 保持现有完整访问语义；程序不得为省弹窗自行切换 Full。工具批准不是用户要求执行操作的替代品，例如用户没有要求提交，就不能因为 Git commit 可自动执行而擅自提交。

只读 CLI 豁免必须验证实际可执行文件、参数、重定向、环境和可能启动的子程序；不能只凭 basename。项目里伪装成 `git` 的程序、`rg --pre`、`find -exec` 等不继承查询豁免。做不到可靠判断时保留确认，不扩大名单凑指标。

普通下载豁免针对能解析完整请求的调用：URL、方法、输出位置明确；配置文件、认证、自定义请求体/方法及上传选项不能被忽略；下载后接执行程序时评估整条调用。它不是“GET 一定没有服务器副作用”的证明，已知触发发布、删除等动作的 URL 仍按真实用途审批。沙箱目前允许出站，界面也不能把这项参数分类描述成系统强制的只下载权限。

## 4. 一次决策、一张卡、执行同一份计划

继续使用现有 runner。每次调用准备一份权威快照，策略、审批展示和执行共用：

- `sessionID / turnID / callID`、原始命令及解析结果。
- 固定 cwd、最终有效 env、解析后的可执行路径与身份。
- 实际有效项目/临时目录、sandbox 或 host、真实网络能力。
- 前后台、超时、TTY/交互输入能力。
- 风险原因、尚缺的授权范围，以及后端计算的可复用候选。

处理顺序：

1. 先读取持久项目配置与仍有效的临时授权，去重并规范化真实路径。
2. 分析本次调用的风险和资源缺口；已经满足的权限不再申请。
3. 无新增需求且符合自动规则时直接执行；否则检查是否命中用户明确选择的复用授权。
4. 不能自动执行时，已知的缺口合并展示。用户一次批准对应同一计划，不先弹目录卡、再对原操作重复弹风险卡。
5. 执行前核对计划与授权仍有效；不能在获批后重读已扩大的项目配置，或换成另一条“等价命令”。
6. 计划变化、资源身份漂移或授权失效时停止并说明原因；不会静默升级执行边界。

复合命令只在分析时分段，执行保持原语义。不能拆坏 `&&`、管道、cwd 和环境继承；也不能把只批准一个片段的 host 权限授给整段脚本。整段需要 host 时，审批展示整段及其真实权限。

## 5. 授权复用：首期交付

### 5.1 生命周期和接口

工具调用审批区分：

| scope | 含义 |
| --- | --- |
| `call` | 仅本次调用，不记录后续放行权 |
| `turn` | 本 session 当前 turn 内，符合后端提供的用途规则可复用 |
| `session` | 当前会话、当前 daemon 运行期内复用；关闭/释放会话、撤销或重启后失效 |

复用必须由用户在审批卡上明确选择；“允许本次”不偷偷记忆。服务端根据待审批计划生成授权候选，客户端只能提交审批 ID 和合法 scope，不能上传任意通配符、命令前缀或授权 key。

实施时迁移现有工具调用中把 `turn` 当作一次批准的 API、UI、事件与测试；默认一次调用改为 `call`，不保留语义相反的兼容路径。能力升级原有 turn/session 生命周期独立校验，不强制套用 call。Computer Use 已有 app consent 不在本次通用命令授权改造范围内。

### 5.2 复用范围怎么匹配

只维护一份引擎授权记录；用途判定复用当前分类与解析结果，不额外实现第二套安全分析。

- 沙箱内可审计的固定非高风险调用：绑定命令/参数、cwd、有效环境、可执行身份、项目身份和资源范围；Ask 用户可授权后续重复运行。允许变化的项目源码属于该次已展示用途，不能把它描述为永远执行第一次的文件内容。
- 已有 Chrome 截图：保留固定程序、输入页面、专用 profile 与输出目录，只放开已有规则允许的截图名称和窗口尺寸。后续变体是否扩大范围逐项检查。
- 任意 `python *`、`npm *`、`git *`、host Shell、未知 host 脚本不提供通配复用。高风险操作、难以绑定的外部对象或新增参数仍单次确认。
- 每次匹配前重新进行风险与边界判断。旧授权不能覆盖新出现的删除、发布、凭据访问或资源扩张。
- 只在匹配器能证明变化处于已批准规则内时复用；不把自然语言“同类操作”直接作为机器授权条件。

host 规则只是用户批准的调用范围，不是操作系统文件沙箱。审批卡必须说明实际离开沙箱、可能具有宿主机及网络能力；不能因为参数写了截图目录就声称程序只能访问这一个目录。可变 HTML 内容不被冒充为固定内容快照。其他 host 命令不能借用截图授权。

Chrome 用途识别可保留为通用复用机制的一种规则，但删除其独立存储/消费路径，不维护两套授权事实。

### 5.3 交互与撤销

- 卡片展示“允许本次”“本轮允许同类操作”“本会话允许同类操作”中后端实际支持的选项，以及固定项、可变项和失效条件。
- 合并审批必须同时覆盖资源授权和操作批准，选定 scope 对两者的期限都明确；高风险只支持 call 时，不悄悄生成更长期资源权。
- session 内提供已有授权的查看/撤销入口，刷新 UI 从后端恢复，不把授权权威记录放 localStorage。
- 多个可复用的相同待审批调用归并展示；可复用批准后重新评估等待调用。选择 call 只释放原调用，其他调用仍须独立决定；不同 Patch/Git 快照及高风险操作不得折叠成一次笼统批准。
- 每个 call 仍只执行一次，拒绝、取消、迟到或跨 session 批准不能重复启动。
- 后台进程启动固定权限。poll/stop 不重复问；可写 stdin/TTY 的授权明确涵盖该进程后续输入，不能自动启动解释器后再通过 write 获得未批准的交互能力。
- 撤销阻止新调用；已运行进程列出并提供停止入口，不承诺撤销会追溯改变进程权限。重启后不自动重放原调用。

## 6. 目录授权与错误恢复

### 6.1 临时授权不修改项目

- Project roots 继续是持久组织配置；新授予的 turn/session 临时目录只归对应会话，由引擎维护。
- 现有 `request_capability` 的 session 目录批准改为临时权限，不再隐式创建、绑定或扩展 Project；明确升级 Code 模式的行为保持独立。
- 已存在的 Project roots 不自动删改。用户真正需要加入项目时走现有项目设置/会话移动功能，不借审批完成组织变更。
- 临时目录按当前 CLI 沙箱能力明确展示为读写，不虚构尚未实现的只读子目录授权。系统工具链可读规则继续与可写项目目录分开。
- 目录归一化及授权合并只有一个权威入口；相关 Code 工具、沙箱和模型上下文消费相同的有效范围。浏览器/文件点击不会因此自动得到 CLI 权限。

### 6.2 不要求模型靠失败学习权限

保留 JSON 工具形式及 `execution=sandbox|host`、`host_access_reason`，不为本目标重做命令语言。

- 明确的项目外路径：服务端可在原调用上准备合并审批，不再强制“失败 → 模型申请目录 → 重发原命令”。隐式资源需求无法分析时，模型仍可显式用 `request_capability` 申请后重试。
- 明确需要 host 而调用仍为 sandbox：返回已有 `host_access_required`，模型以明确理由请求 host；不得在一次普通批准中擅自改为 host。
- 用户拒绝后返回已拒绝的范围；模型不得通过换工具、改写命令或重复申请规避拒绝。
- 新计划获批后直接执行原计划。只有命令本身已失败且需要改变请求时，才发生新的工具调用。
- 输出保留原始错误和实际执行边界。不能只凭 `EACCES`、TLS 错误或非零退出声称一定是沙箱拒绝，更不能由 stderr 中的路径自动创建授权。
- 本轮不添加禁网/项目只读开关，所以不新增“网络写权限”申请参数；若将来增加能力，必须同时交付声明参数、执行约束和结构化拒绝契约。

## 7. 实施顺序与验收

| 切片 | 内容 | 完成条件 |
| --- | --- | --- |
| A1 | 固定基准场景；核对重复审批来源；已验证只读 CLI 与普通下载误报修正 | 不扩张资源边界，Ask 常规读取及 Auto 普通下载无额外弹窗 |
| A2 | 统一计划、调用/turn/session 复用、合并审批、临时目录归属 | 同一已批准用途反复运行不再重复确认 |
