日期：2026-10-19。结论：**保持默认关闭；本批自然采用为 0/4，没有证明净收益。** 后续精简提示和封装的三组结果见 [优化评测](tool-result-memo-optimization.md)，本页保留首批数据。协议与状态恢复验证见 [Engine 接入记录](tool-result-memo-engine.md)。

## 实测结果

修正版完成 4 组、共 8 次主任务和 8 次独立用户追问。请求返回模型名均为 `deepseek-flash`；8 条运行的 HTTP usage 与持久化计数全部一致，没有运行错误。开启组每次请求确实提供 2 个支持 memo 的工具，主任务后续请求包含有效外层结果引用，但模型 **0 次生成 memo、0 次释放、0 次原文回读**。

## 方法与范围

使用官方 DeepSeek `deepseek-flash`、Chat Completions、`reasoning_effort: high`、输出上限 4096。真实模型驱动真实 Engine、内置文件读取与 SQLite，但所有项目证据和会话都是临时合成数据，不读取用户项目、不修改实际 profile 或用户数据库。

每个主任务沿 `next_evidence` 串联 8 份日志，识别各阶段服务、耗时、判定、来源，求总耗时并给出失败阶段和修复动作。4 组任务的数值和链接不同；每组分别关闭／开启 memo，交替执行顺序，减少顺序偏差。用户任务提示不要求 memo；启用组仅使用现有共享提示词和工具 schema，不强制 `tool_choice`，不插入整理轮次。

主任务后另发一次用户问题，要求阶段 2 的原始审计标记。追问前覆盖源文件，精确证据只能来自原有上下文或 canonical 工具快照。该追问及其可能引发的回读、模型续接均单独记录，并纳入完整成本。**没有发生自然释放时，追问成功只说明上下文保留正常，不能声称验证了释放后的真实回读成本。**

主任务按 11 项确定性检查评分：8 条完整阶段记录、总耗时、失败阶段、修复动作。数字或整数字符串等价，其他字段分别评分；还记录最终回答，允许复核格式偏差和事实错误。追问按原始标记精确匹配。模型不生成 memo 也保留在分母；失败、截断、预算耗尽都保存，不自动重试筛选成功样本。

## 计量口径

- 在 HTTP 边界记录每次实际请求、状态、完成标记、模型返回名称、缓存／未缓存输入、内容／推理输出、耗时，以及 memo schema 和引用／释放占位是否实际发送。
- 将 HTTP usage 与 SQLite 会话累计请求／token 逐项核对。只有工具参数、从模型推断的用量或本地估算不能替代真实 usage。
- 成本使用统一峰时费率，避免运行跨时段直接改变比较口径：未缓存输入 $0.30、缓存输入 $0.006、输出（包含推理）$1.20／百万 token。离峰为一半；来源为 2026-10-19 核对的 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)。这是基于 usage 的估算，不是账户账单。
- 输出 token 中推理只计一次；schema、memo 文本、缓存变化和回读的开销全部留在各次真实 usage 中。缓存命中受运行条件影响，交替顺序不能消除所有缓存与随机性偏差。
- 这里只覆盖一种合成链式任务和 4 组对照，不能外推为生产任务成功率或普遍节省比例。

## 评测入口修正与保留记录

首轮使用 12 次主任务请求预算，存在多页日志导致耗尽预算的情况；评分还会因一个数字字符串而整份归零。首轮记录保留为 pilot，不与修正版合并计算主结果。

修正版保留同一日志夹具 `incident-chain-v1`，将 harness 升为 `2`：主任务预算 24 次、追问 4 次；向两组同样说明日志最多 141 行、可用证据工具和数字格式；改为逐项事实评分；记录实际提供的 memo schema。隔离 runner 在执行层也限制为文件切片／历史快照读取，拒绝模型幻觉调用的其他工具。

## 复现与回归

```bash
go test -race ./cmd/memo-prototype

go run ./cmd/memo-prototype -long-benchmark -samples 4 \
  -provider DeepSeek -model deepseek-flash -protocol openai-compatible \
  -max-requests 24 -output /tmp/pudding-memo-long-deepseek.json
```

需要本机已配置的指定 profile 和凭据。每完成一条运行就写一次无凭据 JSON；某条运行错误或未通过质量检查时，完成全部计划样本后返回非零状态，详细结果仍保留。

本地回归覆盖碎片化 SSE 计量、缓存与推理费用、逐项评分、实际 Engine 的三条轨迹（关闭／开启但不生成 memo／生成 memo 后回读）及未声明写工具的拒绝。后两者使用确定性模拟模型验证计量和控制流，不能计入自然采用率。
