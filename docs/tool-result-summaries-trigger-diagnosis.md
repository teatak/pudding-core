2026-10-19。**未发现工具接入或请求时机的程序缺陷；本轮尚未验证到有效的自然采用改进。6 次诊断中仅有 1 次控制尝试，因摘要超长被拒绝，实际释放均为 0。候选提示和结果提醒已撤回，代码仍使用 `summarize-results-v1`，默认关闭。**

## 已确认与尚未确认

上一轮四个开启任务都有正确的工具 schema。根据逐请求引用数与原执行日志，分别有 6、4、2、4 次“已经看到结果，并且下一步仍调用业务工具”的机会，共 **16 次**。因此不能归因于从未获得可附带参数的机会，也不是本地收益门槛拒绝了请求：当时模型根本未输出控制参数。

前三类任务的多数推理 token 出现在最后回答时，读取阶段较少；历史回读任务不完全如此。这与“先收集、最后集中分析”相符，但推理用量不能证明模型内部动机，也不能证明之前的结果已经适合释放。最终要求精确源码引用，保留原文可能是合理选择；这一点仍是推断。

代码路径核对：Engine 在构建普通请求时附加共享提示并装饰工具定义；`Freeze` 为已注册结果提供外层引用，真实 wire 含两个参数定义。新诊断记录证明共享提示在每次实际请求中存在。响应原始参数、合法摘要、实际释放分别统计，避免把“有尝试”和“有效采用”混为一谈。参数只挂在必要调用上；没有下一次必要调用时不应为清理补调用。

- **v2**：把触发点写为每次必要读取前，已确认一份文件或局部事实即可整理；保留路径、行号和短原文引用，不必等待整个任务完成。同时在参数 schema 中重申这些条件。两种任务均未采用。
- **v3 探针**：在成功且不少于 8 KiB 的结果外层附加固定 `summary_hint`，共享提示说明其含义。提醒只标记结果较大，不断言已可丢弃；随既有结果发送，不改业务循环。第 3 次请求的正常文件读取附带了控制，但一次选择五份结果（正文合计 33,416 字节），摘要 **1,143 个 Unicode 字符**，超过执行层 **800** 上限，故被忽略。未截断、释放或追加纠错请求。
- **v4 探针**：保留结果位置提醒，优先每次选择一份已理解的结果，摘要目标 300–500 字符，继续保留 800 硬上限。此次未输出控制参数。

因此，**结果附近的提醒出现过一次尝试，但不能用一个样本证明它导致了采用提升**；更明确的时机和更小粒度也没有证明稳定效果。800 字符约束是本次被拒绝的直接原因，不是上一轮 0 次尝试的原因。不能混淆这两个问题。

六次追问全部正确，无历史回读。合计 34 次模型请求、57 次业务读取、事实 54/54、引用 53/54；第一条引用失败是 `edited_draft_error` 的逐字多行引文与源码缩进不符，保留失败退出状态，未重跑。其余评测通过不等于附加解释全部正确；例如 v1 原任务仍把不可变哈希包的未引用写入笼统称作覆盖，不能据此认定覆盖了正在运行的版本。

所有 usage 完整且与 SQLite 一致，统一峰时估算总计 **$0.218793456**。费率沿用同日核对的 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)：USD/百万 token，未缓存输入 0.30、缓存输入 0.006、含推理输出 1.20；这不是账单。所有释放为零，不能把任一费用升降当成裁剪效果。每格只有一次运行，两个探针还是根据已见结果追加的，不能据此估计总体采用率、因果效应或节省比例。

## 零额外整理请求下的改进方向

1. **保留当前可选语义**：在已有业务响应里携带参数；不强制 tool choice，不新增整理工具，不把漏用当作需要补问的错误。任务已可结束时直接回答。
2. **下一项值得验证的是摘要预算与目标大小是否匹配**。本次模型愿意用 1,143 字符替代 33,416 字节原文，固定 800 上限可能过紧；可以单独测试有硬上限的更大预算，并继续通过本地净收益门槛决定释放。需要计入新增输出、缓存损失、引用质量及之后的回读成本，不能仅凭字节比认定省钱。这里是待验证方案，本次没有提高上限或直接接收被拒绝的摘要。
3. **若继续验证结果位置提醒，应单独控制该变量**：相同业务任务、相同摘要预算，比较有／无提醒并重复多个任务；不得以成功的一次替换失败数据。阈值只提示候选，语义充分性仍由模型判断，原始结果始终可回读。

当前不保留未验证有效的新提示和 `summary_hint`，避免开启实验时平白增加固定成本。保留下来的改进是评测可观测性：逐请求共享提示存在性、系统提示哈希、可见结果引用与字节数、可见工具参数、结束原因，以及实际接受／拒绝／释放计数。采集器不保存推理正文、请求头或凭据。
