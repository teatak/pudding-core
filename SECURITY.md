# Security policy

## Supported versions

Security fixes are provided for the latest published Pudding release. Upgrade to the latest version before
reporting an issue that may already be fixed.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting for
`teatak/pudding-core`:

https://github.com/teatak/pudding-core/security/advisories/new

Include the affected version, platform, impact, reproduction steps, and a minimal proof of concept. Do not send
real API keys, OAuth tokens, personal files, email contents, or production databases.

If private reporting is unavailable, email `yangglive@gmail.com` with the subject `Pudding security report` and
the minimum information needed to establish contact.

We will acknowledge a complete report as soon as practical, investigate it privately, and coordinate disclosure
after a fix is available. Please do not publicly disclose an unresolved vulnerability.
